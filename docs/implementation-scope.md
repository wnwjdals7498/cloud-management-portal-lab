# 구현 범위: Prototype → 기능 확장 → Production

> 2026-10-01. **Production의 의미(D63), VM 없는 지정 범위 무작위 VMM 모의 연동(D64)**은 사용자 확정이다. 상세 작업·프레임워크·모듈은 [1차 구현 계획](implementation-plan-v1.md)의 선정안을 따른다. 나머지 단계 범위·수치는 계획안이며 기존 실행 계획보다 최신 PMT 명세와 구조 재검토 기준표를 먼저 따른다.

| 단계 | 목적 | 포함 범위 | 단계 완료 기준 |
| --- | --- | --- | --- |
| **1. Prototype** | 화면부터 작업 결과까지 최소 흐름 검증 | 고객·관리자 콘솔, 통합 API, MySQL의 최소 구현. 관리자 1명·회원 2명, 로그인·소유권 검사, 고정 사양 1종의 VM 신청·목록·상세·작업 기록. VMM 요청·완료 통지·MSSQL 조회는 모의 연동으로 정상·실패·지연·중복을 재현 | 회원 신청 → 작업 등록 → 모의 결과 → 화면 갱신이 이어지고, 다른 회원 접근과 중복 요청을 차단한다. 모의 VM과 실제 VM을 구분한다 |
| **2. 기능 확장** | 기존 프로젝트의 실제 기능과 실험 완성 | 실제 VMM·Hyper-V 연동과 Rocky VM 생성·SSH 접근. VM 시작·중지·재시작·삭제·사양 변경, 사양 목록·회원 관리, 가상 월별 청구. 인프라·Linux 이중화, 별도 MariaDB/Galera·접근 경로·VPC 관리. Slack·제한 이메일 시험, SMS·테스트 PG 조건부 결정 | 포털 표시와 실제 VM·사양·청구가 일치한다. 소유권·중복·부분 실패·장애 전환·데이터 보존·네트워크 분리 사례의 증거를 남긴다 |
| **3. Production** | 사설망에서 지속 운영 가능한 실습 서비스 | 확장 기능을 인프라 4대+Linux 4대에 배포. 재부팅 후 기동, 서비스·작업 감시, 로그·알림, MySQL·고객 VM/디스크 백업과 복원, 인증서 갱신·비밀정보 관리, 배포·롤백·운영 절차. 운영 부하·용량 한도와 허용 중단 시간 정의 | 호스트 재부팅, 실패/통지 누락 작업 식별과 복구, DB·고객 VM 복원, 배포 롤백, 인증서 갱신을 실제 환경에서 재현하고 운영 기준 충족 여부를 기록한다 |

## 구현 방법과 기존 결정의 연결

- 콘솔은 통합 API를 사용한다. 계정·소유권·작업·청구 규칙은 API에서 관리하며, 콘솔이 VMM에 직접 요청하지 않는다.
- Prototype은 실제 VM 없이 지정 범위의 무작위 VMM 응답으로 진행한다. 모의 연동과 이후 실제 연동은 같은 요청·결과 계약을 사용한다. 모의 시험 결과를 실제 인프라 검증으로 표시하지 않는다.
- 실제 API↔VMM 연동부터 상호 TLS·등록 출발지 제한·최소 권한을 적용한다. 인증·소유권·입력 검증·중복 방지는 Prototype부터 포함한다.
- 페이지 로드 시 API→MSSQL 조회와 VMM→API 완료 통지 방향을 유지한다. 실제 MSSQL 조회 대상, IIS 수신부 기술, 네트워크 설정은 기존 사용자 결정 절차에 따라 구현 전에 정한다.
- VM 실행 코드는 `windows-private-cloud-lab`, 콘솔·API·업무 데이터·요청 계약은 이 저장소에서 관리한다. 구체 프레임워크·배포 도구·제품 버전은 이 범위 합의 뒤 정한다.

## 기능 확장 내부 순서

1. Compute 단독 시험과 실제 연동 계약을 준비한다.
2. 인프라 8대 클러스터 검증과 Linux 8대 이중화 검증을 **따로** 수행한다. 두 시험의 선후는 자원 확인 뒤 정한다. 고객 VM·디스크 보존 전환과 추가 VM의 자동 부팅 제한을 검증한다.
3. 인프라 4대+Linux 4대에서 첫 실제 회원 VM 생성·부팅·SSH 접근을 확인한다. Prototype의 모의 신청은 이 실제 회원 신청을 대신하지 않는다.
4. VM 전체 동작 → 가상 청구 → 관리자 인프라 제어·알림으로 확장한다. Galera 실습은 서비스 MySQL과 분리하고, 실습 노드 배치는 착수 전에 정한다.

## 단계별 제외와 운영 한계

- Prototype: 실제 VM 조작, 클러스터·이중화 구축, 청구 계산, 외부 알림·결제 연동을 제외한다.
- 기능 확장: 백업·복구의 기본 수단을 준비하고, 반복 가능한 운영 검증과 절차 완성은 Production에서 수행한다. 되돌리기 어려운 작업은 복구 방법 확인 후 시험한다.
- Production: 공인 인터넷 서비스, 실제 금전 결제, VM 외 상품, Kubernetes는 포함하지 않는다. Node 비교 구현은 이 세 단계의 완료 조건과 별도로 관리한다.
- 4+4 상시 구성은 역할별 단일 노드이며, 앞선 8대 이중화 검증이 상시 고가용성을 보장하지 않는다. 물리 호스트 1대의 장애 시 서비스 중단을 허용하며, 복구 목표는 별도로 정한다.
