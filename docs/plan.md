# 클라우드 관리포털·Linux IaaS 통합 구축 계획

## 목표와 경계

하나의 PHP·CodeIgniter 포털에서 회원·관리자용 VM 기능과 Linux 인프라 관찰·제어 기능을 제공한다. Hyper-V 자동화는 별도 [`windows-private-cloud-lab`](https://github.com/wnwjdals7498/windows-private-cloud-lab)과 연결하고, Linux 실습 절차와 검증 결과는 [Linux 세부 계획](linux-iaas-ha.md)에 둔다.

포털의 업무 데이터는 MySQL, Linux 단일 DB·Galera 실습은 MariaDB로 구분한다. 회원 대상 상품은 VM만 제공한다. Linux의 Galera·Nginx/Keepalived·VPC는 인프라 운영 실습 범위이며 별도 판매 상품이 아니다. Node 구현은 이 저장소의 **VM 포털 공통 기능·스키마·API·테스트 시나리오**를 공유하며, Linux 인프라 제어 화면까지 재구현하는 범위는 현재 확정하지 않는다.

## 현재 단계

- 저장소 통합 방향과 문서 구조 정리
- [UI 가이드](ui/guide.md)와 [HTML 목업](ui/mockup.html) 제작
- [첫 동작 결과 세부 계획](first-working-slice.md) 수립 중
- 실제 포털·인프라 구현, 배포, 검증은 아직 시작하지 않음

## 단계

1. 공식 지원 버전, 실행 환경, 라이선스와 보안 가이드를 확인한다. 테스트 계정과 예제 데이터만 준비한다.
2. 회원·관리자 역할, VM 요청·작업 상태·사양 변경 이력·청구 데이터의 계약을 정의한다. Linux 제어 작업의 입력·결과·실패 상태도 구분한다. 로그 형식은 구현 전에 결정한다.
3. 관리자 계정 생성과 회원 관리, 인증·인가를 구현한다. 회원은 본인 VM만 조회·조작하도록 검증한다.
4. VM 신청 시 승인 대기 없이 생성 작업을 시작한다. PowerShell/Hyper-V 호출, 작업 상태, 실패·재시도·복구를 연결한다.
5. 시작·중지·재시작·삭제·사양 변경을 회원·관리자 포털에서 검증한다.
6. Linux VM·MariaDB Galera·Nginx/Keepalived·VPC를 [세부 계획](linux-iaas-ha.md)에 따라 구축·검증한다. 포털 제어 기능은 실제 작업 결과와 일치하도록 연결한다.
7. 생성부터 삭제까지의 기간과 실제 적용 사양으로 월별 사용분을 계산한다. 매월 1일 전월 청구서를 생성하고, 전원 상태와 무관한 계산을 검증한다.
8. Slack 알림과 제한된 이메일 발송을 검증한다. SMS 테스트 환경과 Toss Payments 공식 테스트 환경을 확인한 뒤 조건부 범위를 결정한다.
9. 입력 검증, 권한 우회, 민감정보 노출과 주요 작업 실패 사례를 점검한다. 재현 가능한 테스트 결과를 남긴다.

## 완료 확인

- 회원 신청 뒤 실제 테스트 VM 생성 작업이 즉시 시작된다.
- 권한과 다섯 VM 조작이 실제 Hyper-V 상태와 일치한다.
- 사양 변경 구간과 생성·삭제 시점을 반영한 전월 청구서가 매월 1일 생성된다.
- Linux 장애·재합류·접근 경로·VPC 동작과 포털 제어 결과가 재현 가능하다.
- 공개 자료와 로그에 민감정보가 포함되지 않는다.

## 이후 결정

제품 버전, 가상 단가, 로그·테스트 증거 형식, Linux 제어 작업 실행 방식, VPC 기술, SMS 환경, 테스트 PG 연동 여부는 해당 단계 전에 결정한다. 실제 결제와 VM 외 추가 상품은 구현하지 않는다.
