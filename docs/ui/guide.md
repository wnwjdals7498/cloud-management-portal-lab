# 클라우드 관리포털 UI 가이드 · 초안

> 화면 설계용 문서. [HTML 목업](mockup.html)의 수치·VM·이력은 예시이며 실제 운영 상태가 아니다.

## 화면 목표

- 첫 화면에서 **전체 상태 → 처리할 문제 → 최근 작업** 순서로 읽힌다.
- 회원은 자신의 VM·청구만, 관리자는 전체 VM·인프라 작업을 본다. 권한 제한은 화면 숨김뿐 아니라 서버에서 강제한다.
- 긴 작업은 요청 접수, 실행 중, 성공, 실패를 각각 표시한다. 버튼 클릭을 실제 작업 완료로 표현하지 않는다.
- Linux 실습의 Galera·접근 경로·VPC는 운영 화면에서 관리하되 회원 대상 판매 상품과 구분한다.

## 정보 구조

| 메뉴 | 회원 | 관리자 |
| --- | --- | --- |
| 개요 | 본인 VM·최근 요청·청구 요약 | 전체 VM·문제·최근 작업 |
| 가상 머신 | 본인 VM 신청·조회·조작 | 전체 VM·회원별 조회·조작 |
| 인프라 | 없음 | Linux 노드·접근 경로·VPC와 Windows Hyper-V 호스트 상태·작업·검증 기록 |
| 청구 | 본인 청구서 | 전체 청구서와 발행 상태 |
| 작업 기록 | 본인 작업 | 전체 작업·오류·재시도 이력 |

## 시각 규칙

- 배경은 밝은 회색, 탐색 영역은 진한 남색, 주요 동작은 파랑을 사용한다. 한 화면의 강조색은 제한한다.
- 카드에는 제목, 핵심 값, 기준 시각을 함께 둔다. 큰 숫자만으로 의미를 추측하게 하지 않는다.
- 상태는 텍스트와 색을 함께 사용한다: 정상(청록), 진행 중(파랑), 주의(주황), 실패(빨강), 계획(회색).
- 화면 폭이 좁으면 사이드바를 상단 메뉴로 바꾸고 표는 가로 스크롤 영역에 둔다. 내용과 동작을 삭제해 폭을 맞추지 않는다.
- 본문 14px 이상, 버튼 높이 40px 이상, 키보드 포커스 표시, 충분한 명도 대비를 기본으로 한다.

## 핵심 화면

1. **개요:** VM 총량, 진행 중 작업, 인프라 주의 상태, 예상 청구액과 최근 이력.
2. **VM 목록/상세:** 소유자, 실제 상태, 적용 사양, 마지막 동기화 시각, 허용된 조작. 삭제·사양 변경에는 영향과 대상 VM을 다시 보여준다.
3. **인프라:** Galera 노드와 정족수, Nginx·Keepalived 경로, VPC 연결 상태. 관찰 값과 사용자의 제어 요청을 분리한다.
   Windows 호스트·VM 자동화의 실습·검증 화면도 이 관리자 메뉴 안에 둔다. 실제 PowerShell 실행 코드는 `windows-private-cloud-lab`이 관리한다.
4. **청구:** 기간, 사양 변경 구간, 단가, 사용 시간, 청구 상태의 근거를 펼쳐 볼 수 있게 한다.
5. **작업 기록:** 요청 시각, 대상, 실행 단계, 결과, 오류 요약, 재시도 여부.

## 공통 컴포넌트

- **상태 배지:** 짧은 상태명과 일관된 색. 상태 정의를 API 계약과 맞춘다.
- **주요 버튼:** 화면당 대표 동작 하나만 강하게 강조한다. 보조 동작은 윤곽 버튼이나 텍스트 버튼을 쓴다.
- **확인 대화상자:** 대상 이름·영향·되돌릴 수 있는지 표시한다. 목업의 버튼은 실제 VM을 조작하지 않는다.
- **빈 상태:** 왜 비어 있는지와 다음 동작을 알려준다. 권한 부족은 빈 목록과 구분한다.
- **시간:** 절대 시각과 시간대(Asia/Seoul)를 표시한다. 작업 진행 상태는 마지막 갱신 시각을 노출한다.

## 구현 전 확인

회원·관리자별 정보 노출, 상태 문구, 실제 작업 단계, 청구 계산 근거, 모바일 폭과 키보드 동작을 실제 API·데이터와 대조한다. 목업의 데모 수치를 서비스 검증 결과로 사용하지 않는다.
