# VMM 모의 연동

원문: [1차 구현 계획](../implementation-plan-v1.md) 7·8절. [참조 안내](README.md).

사용자 확정: **실제 VM 없이 지정 범위 안에서 무작위 응답을 보낸다.** 아래 숫자는 계획의 기본 제안이며 설정값으로 관리한다.

| 시나리오 | 가중치 | 동작 |
| --- | --- | --- |
| 정상 | 70 | 2~15초 뒤 성공·통지 |
| 실패 | 15 | 2~15초 뒤 허용 오류·실패 통지 |
| 늦은 완료 | 5 | 30~60초 뒤 성공 통지, API 대기 기준 20초 초과 |
| 통지 누락 | 5 | 2~15초 뒤 모의 상태 성공, 최초 통지 누락 |
| 중복 통지 | 5 | 성공 통지 후 1~3초 뒤 동일 event_id 재전송 |

## 구현 규칙

- 최초 범위는 생성·고정 사양 1종이다. 유효 요청 접수는 202이며 실행 결과만 추첨한다. 입력·권한·멱등 오류를 무작위로 통과시키지 않는다.
- 요청마다 한 번 추첨하고 입력·seed·알고리즘 버전·profile 버전·결과·due_at을 저장한다. 재조회·중복 요청·재시작으로 재추첨하지 않는다.
- 가중치 합 100, 음수 없음, 지연 min≤max, 허용 오류·상한을 기동 때 검사한다. 잘못된 설정으로 실행하지 않는다.
- 지연은 DB 예정 통지와 CLI dispatcher로 처리한다. HTTP 요청에서 sleep하지 않는다. 초기 제안은 대기 100건·dispatcher 1개다.
- 기본 오류는 `SIM_IMAGE_UNAVAILABLE`, `SIM_STORAGE_FULL`, `SIM_EXECUTION_FAILED`다.
- 테스트에서는 고정 seed·저장 결과·개발 CLI의 시나리오 강제 지정으로 분기를 재현한다.
- 누락은 `reconciliation_required`로 남기며 명시적 재통지 등으로 복구한다. 모의 데이터·화면·로그에는 `mode=simulated`를 붙인다.
- Production은 모의 adapter와 개발 강제 설정을 거부한다. 모의 SSH 정보를 실제 접속 주소로 표시하지 않는다.

## 검증 자료

`fixtures/simulator/reference-flows/`에 다섯 시나리오별 요청·접수 응답·조회값·callback·기대 DB 상태·타임라인을 작성한다. 모의 서버와 API의 내부 구현을 공유하지 않는 계약 fixture를 기준으로 검증한다. 재시작 후 예정 통지 복구, 늦은 통지, 중복의 단일 반영도 확인한다.
