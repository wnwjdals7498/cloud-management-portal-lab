## 적용 단계와 순서

G0 자원 확인 후 P1에서 프록시 경계(FS-058), 계정 준비(FS-003), 로그인·CSRF·권한(FS-004~006)을 순차 연결한다. P4에서 개요·VM·작업 조회(FS-007~009), P2에서 고정 사양 관리 기반(FS-010), E2에서 관리자 회원 관리(FS-011)를 적용한다. E3에서 불변 단가 규칙(FS-035)과 사용 구간(FS-036)을 정한 뒤 월별 청구 발행(FS-037), 조회·정책 허용 상태 관리(FS-038)를 수행한다. E4에서 알림 사건과 목적지 정책을 먼저 확정한 뒤 Slack(FS-044), 제한 이메일(FS-045)을 구성한다. SMS(FS-046)와 테스트 PG(FS-047)는 공식 시험 가능 조건과 명시적 결정이 충족될 때만 연동한다.

G0 전 Prototype 실행은 불가하며 실습 자원은 미확인이다. 초기 단계에서는 VM 없는 모의 응답만 허용한다. Billing·Notifications는 E 단계에서만 추가하고, 미확정 단가·반올림·청구 상태·회원 변경 필드·알림 사건·SMS/PG 조건은 정책 확정 전 구현 계약으로 가정하지 않는다.

## FS-003 초기 관리자·회원 계정 준비

<a id="fs-003"></a>
### FS-003 초기 관리자·회원 계정 준비

- **목적:** 공개 가입을 열지 않고 P1 인증 검증에 필요한 제한 계정을 준비한다.
- **추가 범위:** 초기 계정 준비 사용 사례, 역할 허용 목록 검사, 기존 계정 재실행 판정, 안전한 결과 요약.
- **수정 범위:** Identity가 소유하는 Shield 계정·그룹 계약에 준비 절차를 연결한다. 로그인 식별과 역할만 입력 계약으로 받고 계정 준비 권한을 서버 측에서 판정한다.
- **삭제 범위:** 공개 회원가입, 브라우저에서의 역할 선택·초기 관리자 승격, 인증정보 로그 출력은 허용하지 않는다.
- **goal:** 허가된 운영 맥락에서만 초기 관리자·시험 회원 계정 참조와 실제 역할을 확인하고 재실행해도 중복 계정이나 권한 확대가 생기지 않는다.
- **non-goal:** 비밀 발급·전달 채널의 자동 구축, 일반 사용자 가입, 운영 고객 계정 대량 적재는 범위 밖이다.
- **목표-input:** `account_definitions`는 운영자가 제공하는 계정 식별·요청 역할·초기 인증정보의 의미이며 Identity 준비 절차가 받는다. `execution_context`는 서버가 확인한 준비 권한·대상 환경·요청 추적 문맥이다.
- **목표-output:** `account_refs`는 생성 또는 기존 확인된 계정의 내부 참조로 운영자에게 반환된다. `assigned_roles`는 DB에서 재조회한 실제 역할이다. `creation_result`는 생성·기존 확인·검증 거부·저장 실패를 구분한다.
- **구현 동작:** 환경과 실행 권한을 먼저 확인하고, 역할 allowlist 및 식별 중복 여부를 검증한다. Identity 트랜잭션 안에서 계정·그룹 관계를 저장하고 고유 제약 충돌은 기존 계정 확인 또는 명시적 충돌로 처리한다. 인증정보는 해시 전용 라이브러리 경계에서 처리하며 응답·로그에 원문을 되돌리지 않는다. 커밋 후 재조회한 계정·역할만 결과로 내고, 실패 시 부분 계정/역할이 남지 않도록 롤백한다.
- **책임·의존 계약:** Identity가 계정·역할 저장과 재실행 판정을 소유하고 운영 CLI 또는 승인된 준비 호출자가 입력을 공급한다. FS-057 DB와 FS-004 인증이 선행되어야 하며 Audit 기록은 같은 변경 트랜잭션에 포함한다. P1에서 구현한다.
- **코드동작확인 Test방식:** 초기 생성, 동일 정의 재실행, 중복 식별, 금지 역할, 권한 없는 호출, 저장 중 실패를 관찰한다. DB의 계정 수·그룹 관계·해시 존재를 재조회하고 원문 인증정보가 저장·반환되지 않는지 확인한다. 공개 가입 라우트가 없어야 한다.
- **코드동작확인 로깅방식:** `request_id`와 감사 사건에 실행 행위자·계정 참조·역할·생성/기존/거부 판정을 기록한다. 비밀번호·해시·세션 원문은 제외한다. 감사 행과 DB 역할·CLI 결과를 같은 추적으로 대조한다.
- **완료·반환 증거:** 허용된 준비 동작·재실행 결과·공개 가입 차단의 Test 식별자, 정제된 DB/감사 대조 참조, 미해결 운영 계정 전달 절차를 반환한다. 실제 Test는 구현 후 별도 실행하며 이 계획에서는 실행하지 않았다.

## FS-004 로그인·로그아웃·현재 사용자

<a id="fs-004"></a>
### FS-004 로그인·로그아웃·현재 사용자

- **목적:** API 세션으로 신원을 확인하고 종료된 인증 상태의 재사용을 막는다.
- **추가 범위:** Shield 세션 기반 로그인·종료·현재 사용자 사용 사례, 로그인 성공 시 세션 식별자 재발급, 역할 포함 공개 프로필 변환.
- **수정 범위:** API 인증 응답을 JSON 계약으로 제한하고 콘솔 두 곳이 각자 host-only 쿠키를 쓰도록 연결한다.
- **삭제 범위:** 브라우저 제공 사용자 ID를 인증 근거로 쓰거나 토큰·쿠키를 업무 응답에 복제하는 동작은 금지한다.
- **goal:** 인증 성공·거부, 세션 재발급·종료 및 현재 사용자 조회가 일관되고 콘솔별 세션 격리가 유지된다.
- **non-goal:** 외부 SSO, 공개 가입, 계정 복구·다단계 인증 정책은 별도 결정 없이는 포함하지 않는다.
- **목표-input:** `login_identifier`와 `credential`은 브라우저가 TLS 및 콘솔 프록시를 통해 API에 제출하는 증명 의미다. `session_context`는 API의 기존 세션 상태, `auth_action`은 로그인·로그아웃·현재 사용자 요청 구분이다.
- **목표-output:** `authentication_result`는 성공/거부 분류, `user_context`는 허용된 사용자 참조와 역할, `session_transition`은 재발급·종료 여부이며 API가 콘솔에 전달한다. 세션 원문은 쿠키 경계에서만 다룬다.
- **구현 동작:** 요청 출처·입력 형식과 로그인 시도 제한의 확정 정책을 검증한 뒤 Shield가 자격 증명을 확인한다. 성공 시 세션 ID를 재생성하고 사용자·역할을 세션 저장소에 기록한다. 로그아웃은 세션 무효화와 쿠키 만료를 수행한다. 현재 사용자 조회는 서버 세션을 다시 확인한다. MySQL 세션 저장과 인증 상태 갱신을 원자적으로 처리하고 저장 실패 시 인증 성공을 응답하지 않는다. 인증 실패는 401, 권한 부족은 403, 응답 유실/DB 장애는 일반 실패로 구분하며 인증 실패 이유는 외부에 과도하게 노출하지 않는다.
- **책임·의존 계약:** Identity가 인증 및 공개 사용자 문맥을 제공하고 API HTTP 경계가 상태 코드/쿠키를 변환한다. FS-003, FS-057, FS-058이 선행이다. P1 적용.
- **코드동작확인 Test방식:** 정상·오인증·없는 사용자 간 응답 차이 노출 여부, 세션 고정 공격용 이전 ID 재사용, 로그아웃 후 재사용, 동시 API 세션, 두 콘솔 간 쿠키 전송 여부를 확인한다. DB 세션 행과 브라우저 cookie 상태 및 응답 신원을 대조한다.
- **코드동작확인 로깅방식:** 기술 로그에는 인증 결과 분류·요청 ID·소요시간을, 감사에는 행위자 참조(성공 시)·역할·성공/거부·종료만 기록한다. 비밀번호·쿠키·세션 식별자·CSRF 값은 마스킹이 아니라 완전 제외한다. API 응답·세션 저장소·감사 결과를 대조한다.
- **완료·반환 증거:** API 계약 결과, 역할별 브라우저 흐름, 세션 재발급/폐기 및 콘솔 쿠키 격리의 실행 Test 기록을 반환한다. 비밀 없는 정제 증거만 남긴다.

## FS-005 CSRF 준비·검증

<a id="fs-005"></a>
### FS-005 CSRF 준비·검증

- **목적:** 세션 인증을 쓰는 변경 요청에 세션 연계 위조 방지 검증을 적용한다.
- **추가 범위:** 토큰 초기화·요청 검증 사용 사례와 변경 메서드 보호 계약.
- **수정 범위:** 콘솔 요청 유틸리티가 증명 메타데이터를 받아 변경 요청에 전달하고 API Filter가 인증과 연계해 검증하도록 연결한다.
- **삭제 범위:** CSRF 증명을 로그에 남기거나 내부 VMM callback에 브라우저 CSRF를 요구하는 동작을 배제한다.
- **goal:** 정상 세션의 변경 요청만 검증 통과하고 누락·변조·타 세션 증명은 업무 처리 전에 거부된다.
- **non-goal:** callback 서비스 인증을 대체하거나 CSRF 없이 허용되는 읽기 메서드의 정책을 임의로 확장하지 않는다.
- **목표-input:** `session_context`는 API가 확인한 인증 세션, `csrf_proof`는 콘솔이 CSRF 초기화 응답에서 받아 변경 요청에 싣는 증명, `request_method`는 API 라우터가 전달하는 HTTP 동작 의미다.
- **목표-output:** `csrf_metadata`는 브라우저 요청 계층이 사용할 제출 방식·증명이며 비밀 원문은 응답/전송 경계로 한정된다. `validation_result`는 업무 호출 전 허용 또는 거부 사유로 API가 응답한다.
- **구현 동작:** 프록시 요청 ID와 인증 세션을 확립하고, 변경 메서드에서만 증명 존재·형식·세션 연계를 검증한다. 통과 후 업무 사용 사례로 진행한다. 거부는 JSON 403 또는 계약된 CSRF 오류로 끝내며 VM·회원·청구 데이터 변경이 없어야 한다. 세션 재생성/로그아웃 때 이전 증명은 무효화하고, 토큰 검증과 변경 실행 사이의 세션 일관성은 Shield/세션 저장 경계가 보장한다. 내부 callback은 별도 서비스 인증 필터로 분리한다.
- **책임·의존 계약:** API Filter/Identity가 증명 수명주기와 검증을 소유하고 콘솔은 받은 증명을 그대로 제출한다. FS-004·058이 선행이다. P1 적용.
- **코드동작확인 Test방식:** 정상 증명, 누락, 변조, 다른 세션의 증명, 로그아웃 후 이전 증명, 읽기/변경 메서드 경계를 호출한다. 거부 전후 DB 행·감사 상태가 동일하고 내부 callback이 CSRF 검사 대신 서비스 인증에 걸리는지 확인한다.
- **코드동작확인 로깅방식:** 사건 `csrf_validation`에 요청 ID·경로 분류·통과/실패 이유만 기록하고 증명·쿠키 헤더는 제외한다. API 응답, 업무 DB 불변, 보안 감사/테스트 기록을 같은 요청 ID로 대조한다.
- **완료·반환 증거:** 토큰 획득·정상 제출·거부 분기와 변경 없음 증거, callback 필터 분리 확인을 반환한다.

## FS-006 역할·소유권 검사

<a id="fs-006"></a>
### FS-006 역할·소유권 검사

- **목적:** 서버 검증 역할과 저장된 소유 관계로 모든 데이터·동작의 접근 범위를 정한다.
- **추가 범위:** 재사용 가능한 권한 판정 의미와 사용자 범위 조건, 거부/숨김 응답 규칙.
- **수정 범위:** Vm·Jobs·Billing의 각 사용 사례가 Identity 문맥을 받고 자기 소유 관계를 적용하도록 계약한다.
- **삭제 범위:** UI에서 버튼을 숨기는 것만으로 권한을 인정하거나 클라이언트 user ID/role을 신뢰하는 처리를 금지한다.
- **goal:** 회원은 본인 대상만 보고 관리자는 승인된 전체 업무를 수행하며 타인 자원 세부정보가 누출되지 않는다.
- **non-goal:** 관리자의 모든 업무 제한을 한 범용 우회 권한으로 합치지 않는다. 세부 관리자 권한표는 별도 확정한다.
- **목표-input:** `actor_context`는 FS-004가 서버 세션에서 만든 사용자 참조·역할, `resource_ref`는 각 모듈의 VM/작업/청구/회원 참조, `requested_action`은 조회·변경 의미, `ownership`은 해당 모듈 저장소에서 얻는 소유 관계다.
- **목표-output:** `authorization_result`는 사용 사례 내부 판정, `visible_scope`는 조회 저장소에 적용할 회원/관리자 필터, `denial_reason`은 공개 가능한 분류이며 API는 숨길 타인 객체에 404를 반환한다.
- **구현 동작:** 인증 문맥을 확인하고 역할별 동작 정책을 판정한다. 단일 객체는 소유 관계를 조회해 일치 여부를 검사하고, 목록은 쿼리 자체에 소유 조건을 적용한다. 판정 후 같은 사용 사례 안에서 업무 처리를 수행하며 상태변경은 모듈 트랜잭션과 감사 기록에 묶는다. 타인 객체는 404, 인증 없음 401, 명시적 권한 부족 403으로 변환한다. 거부 로그 외에 객체 필드·상태는 반환하지 않고 DB 변경 전에 중단한다.
- **책임·의존 계약:** Identity는 신원·역할만 공급, 각 소유 모듈(Vm, Jobs, Billing, Identity)은 관계 데이터와 액션 정책을 소유한다. FS-004 선행, 기능별 각 P/E 단계에서 소비.
- **코드동작확인 Test방식:** 회원 두 명 사이 ID 치환, 관리자 URL 직접 호출, 목록 필터 우회, 소유관계 변경 경합, VM·작업·청구별 조회와 변경을 시험한다. 응답 본문에 타인 필드가 없고 거부 요청의 DB/원장 변화가 없는지 확인한다.
- **코드동작확인 로깅방식:** 감사에는 행위자·대상 참조·동작·허용/거부, 기술 로그에는 모듈·추적 ID·결과 분류를 기록한다. 불필요한 대상 개인정보를 넣지 않고 DB 쿼리 범위·응답·감사 원장을 대조한다.
- **완료·반환 증거:** 역할·소유권 조합표와 각 모듈의 우회/거부 Test 결과, 숨김 응답 및 무변경 근거를 반환한다.

## FS-007 고객·관리자 개요 화면

<a id="fs-007"></a>
### FS-007 고객·관리자 개요 화면

- **목적:** 사용자 역할에 맞는 현재 상태, 문제, 최근 작업과 데이터 최신성을 이해할 수 있게 보여준다.
- **추가 범위:** 콘솔 화면 표시·요약 API 조합·빈 상태/오류/오래된 값 표시 규칙.
- **수정 범위:** 고객·관리자 콘솔은 API JSON만 소비하고 권한 범위는 서버 응답에 따른다. E 단계 요약은 실제 모듈 제공 후 점진적으로 연결한다.
- **삭제 범위:** 화면에서 받은 값으로 권한을 결정하거나 미구현 청구·인프라 메뉴를 기능으로 가장하지 않는다.
- **goal:** P4에서 모의 VM·작업의 접수/완료와 오류·최신성을 역할별로 구분해 표시한다.
- **non-goal:** Prototype에서 Billing/Infrastructure 실데이터나 외부 알림을 표시하지 않는다.
- **목표-input:** `user_context`는 로그인 API가 콘솔에 준 역할 문맥, `summary_data`는 API가 허용 범위의 VM·작업 요약으로 공급하며 이후 청구/인프라 값은 해당 단계 적용 뒤에만 포함한다. `observed_at`은 API 데이터 기준 시각이다.
- **목표-output:** `overview_view`는 콘솔이 그리는 요약·최근 작업·문제 문구, `freshness_indicator`는 최신/오래됨/조회 실패 표시, `available_navigation`은 현재 단계와 사용자 역할에 허용된 이동 항목이다.
- **구현 동작:** 화면 진입 시 현재 사용자와 요약 API를 호출하고 API에서 신원·소유 범위를 검증한다. 받은 요약의 모드·관찰 시각·작업 상태를 의미에 맞게 렌더링하며 접수를 완료로 표시하지 않는다. 부분 조회 실패는 가능한 값과 오류/최신성을 함께 보여준다. 화면 새로고침은 읽기 전용이며 데이터 지속성은 원천 업무 모듈에 둔다. 세션 만료·CSRF/네트워크 오류는 로그인 또는 재시도 안내로 종료한다.
- **책임·의존 계약:** 콘솔은 표현·접근성·API 호출을 소유하고 API의 Vm/Jobs 조회가 데이터를 공급한다. FS-004~006·058, FS-008~009 선행; P4 적용.
- **코드동작확인 Test방식:** 고객/관리자·빈 데이터·진행/실패·오래된 관찰·API 오류·세션 만료를 브라우저에서 관찰한다. 소형 화면·키보드 탐색·색에 의존하지 않는 상태 문구와 API 응답의 의미/범위 일치를 확인한다.
- **코드동작확인 로깅방식:** API 기술 로그에 요약 조회·범위 분류·기준 시각·실패를 남긴다. 브라우저 캡처는 식별 정보를 정제하고 API 응답과 DB 조회 결과를 같은 request ID/관찰 시각으로 대조한다.
- **완료·반환 증거:** 역할별 화면 흐름, 핵심 상태/최신성 표기, 접근성 및 오류 표시의 정제 캡처와 API/DB 대조 기록을 반환한다.

## FS-008 VM 목록·상세 조회

<a id="fs-008"></a>
### FS-008 VM 목록·상세 조회

- **목적:** 소유 범위 VM과 현재 적용 사양·작업·관찰 상태를 서로 혼동하지 않게 조회한다.
- **추가 범위:** 서버 페이지 범위가 적용된 목록 및 한 건 상세의 표시 계약.
- **수정 범위:** Vm 조회가 Jobs 작업 요약과 상태 관찰을 조합하되 VM 자체의 현재 전원/게스트 관찰과 작업 결과를 분리한다.
- **삭제 범위:** 모의 VM에 실제 SSH·접속 주소를 노출하거나 API 외부 ID를 사용자 입력으로 받지 않는다.
- **goal:** 회원 소유 VM과 관리자의 허용된 전체 VM을 사양·상태 최신성·실행환경과 함께 표시한다.
- **non-goal:** P단계에서 실제 VMM 상태 조회나 실제 접속 가능성을 주장하지 않는다.
- **목표-input:** `actor_context`는 FS-006에서 검증할 사용자 문맥, `vm_ref`는 상세 대상 ID, `list_scope`는 서버가 허용하는 정렬/페이지 범위 의미, `state_observation`은 Vm/StatusReader가 공급하는 저장/외부 관찰과 시각이다.
- **목표-output:** `vm_view`는 소유자 표시 범위·적용 사양·전원/게스트 관찰·작업 상태, `allowed_actions`는 권한·현재 상태로 허용 가능한 동작, `freshness`는 마지막 관찰과 실패 분류, `mode`는 모의/실제 경계다. API가 콘솔에 제공한다.
- **구현 동작:** 요청 인증·페이지 조건을 검증하고 목록 쿼리에 서버 소유 필터를 적용한다. 상세는 VM 참조와 소유권을 확인한 뒤 적용 사양·최신 Jobs 요약·저장 관찰을 읽는다. 외부 StatusReader 사용은 실제 단계/계약이 승인된 뒤 별도이며 조회 실패 시 기존 관찰값과 오래됨을 반환한다. 읽기는 트랜잭션 스냅샷 또는 일관된 조회 시점으로 묶고, 업무 행을 갱신하지 않는다. 미존재/타인 자원은 동일한 404, DB 장애는 일반 실패다.
- **책임·의존 계약:** Vm은 VM·소유자·사양·관찰을 소유, Jobs는 작업 요약 제공, API가 응답 조합. FS-006·009·010 선행; P4 화면 적용, 조회 계약은 P2 이후 소비.
- **코드동작확인 Test방식:** 본인/관리자·타인·빈 목록·페이지 범위·조회 실패·작업 접수와 완료·모의 접속 표현을 비교한다. 응답·화면 값이 Vm/Jobs/관찰 행과 일치하고 조회가 원장 상태를 바꾸지 않는지 확인한다.
- **코드동작확인 로깅방식:** request ID와 VM 참조·조회 범위·mode·신선도·오류 분류만 기록한다. 내부 주소·전체 소유 데이터는 배제하고 응답의 관찰 시각과 저장값/adapter 응답을 대조한다.
- **완료·반환 증거:** 소유권·상태 구분·최신성·모의 접속 표현에 대한 API, 화면, 저장 상태 대조 결과를 반환한다.

## FS-009 작업 기록·상세 조회

<a id="fs-009"></a>
### FS-009 작업 기록·상세 조회

- **목적:** 요청부터 시도·외부 결과·재확인까지의 실행 이력을 권한 범위에서 추적한다.
- **추가 범위:** 작업 목록/상세 조회에서 타임라인·실패 분류·미확정 이유를 보여준다.
- **수정 범위:** Jobs 조회 계약이 attempt·callback inbox의 정제 사건과 recovery 상태를 연결한다.
- **삭제 범위:** 작업 응답 하나를 전체 이력으로 간주하거나 인증되지 않은 타임라인을 노출하지 않는다.
- **goal:** 운영자와 요청자가 접수·전달·완료·재확인 단계의 사실을 구분해 파악한다.
- **non-goal:** 이 조회 기능 자체가 작업을 재시도하거나 상태를 고치지 않는다.
- **목표-input:** `actor_context`는 FS-006 검증 신원, `job_ref`는 대상 작업 참조, `history_scope`는 서버 허용 기간·상태·대상·페이지 범위의 의미로 콘솔이 요청하고 Jobs가 적용한다.
- **목표-output:** `job_history`는 요청·각 attempt·단계·결과·오류 분류·통지/관찰 시각, `recovery_context`는 재확인 필요 여부·정책상 가능 동작·미확정 이유이며 API가 콘솔에 반환한다.
- **구현 동작:** 인증·소유권·조회 조건을 검증하고 작업 및 관련 시도/inbox를 일관된 읽기 트랜잭션에서 조회한다. 사건은 발생/관찰 시각 순으로 표시하고 접수·외부 실행·결과 확정을 구분한다. 실패 또는 누락 callback은 근거와 재확인 필요로 나타내며 조회 중 상태를 변경하지 않는다. 동시 새 사건이 생기면 기준 시각/페이지 의미를 안정적으로 적용하고 권한 없는 작업은 404 처리한다.
- **책임·의존 계약:** Jobs가 작업·시도·inbox 이력 소유, Identity 권한과 Vm 참조 표시를 조합한다. FS-006·012~020 선행; P4 적용.
- **코드동작확인 Test방식:** 회원 간 이력 차단, 관리자 조회, 성공·실패·지연·중복 callback·재시도 타임라인, 동시 기록 추가를 검사한다. 각 화면 사건과 DB attempt/inbox/event 시각·식별자가 대응하고 조회가 상태를 변경하지 않아야 한다.
- **코드동작확인 로깅방식:** request ID·작업 참조·범위·결과 수만 기술 로그에 남긴다. Test 증거는 표시 타임라인을 동일 작업의 Jobs·inbox·attempt 및 사건 로그와 대조하며 callback 본문·비밀정보는 제외한다.
- **완료·반환 증거:** 정제된 역할별 타임라인과 데이터 원장 대조, 재확인 상태 구분 Test 결과를 반환한다.

## FS-010 VM 사양 조회·관리

<a id="fs-010"></a>
### FS-010 VM 사양 조회·관리

- **목적:** 신청 가능한 사양을 서버가 통제하고 사양 변경의 과거 근거를 보존한다.
- **추가 범위:** 고정 모의 사양 조회와 이후 관리자 사양/가용성 변경·revision 이력.
- **수정 범위:** Vm 신청은 클라이언트 사양값 대신 서버 사양 참조를 사용하고 생성 당시 revision을 고정한다.
- **삭제 범위:** 회원이 임의 CPU·메모리·디스크·네트워크 값을 제출해 임의 자원을 만드는 동작을 제외한다.
- **goal:** 현재 선택 가능 사양과 이전 사양 정의를 구별하고 이후 사양 수정이 기존 VM에 소급되지 않는다.
- **non-goal:** G1 전 실습 VM의 실제 용량·네트워크 수치를 정하거나 자원을 예약하지 않는다.
- **목표-input:** `profile_ref`는 콘솔 또는 VM 생성 사용 사례가 제출하는 사양 식별, `profile_definition`은 관리자가 정한 자원/허용 네트워크 속성의 의미, `availability`는 신청 허용 상태, `actor_context`는 서버 인증 권한이다.
- **목표-output:** `selectable_profiles`는 신청 화면에 API가 제공하는 공개 사양, `profile_revision`은 불변 버전과 변경 이력 참조, `validation_result`는 사용 사례가 반환하는 허용/거부 이유다.
- **구현 동작:** 조회 시 공개 가능한 속성만 반환한다. 변경 요청은 관리자 권한, 속성 스키마, 유효성, 다른 활성 revision과의 모순을 검사한다. 적용 시작/종료·겹침·용량 같은 정책은 먼저 확정한다. 저장 시 기존 revision은 불변으로 닫고 새 revision·감사를 한 DB 트랜잭션으로 기록하며 동시 변경은 revision 잠금/낙관적 버전 검사로 하나만 성공시킨다. VM 신청은 처리 트랜잭션에서 가용 revision을 재확인해 경합을 막는다. 실패 시 구 revision을 유지하고 미허용/비활성 참조는 4xx로 종료한다.
- **책임·의존 계약:** Vm이 profile 및 VM 적용 revision을 소유, Identity/Audit가 관리자 권한·변경 행위 제공, 콘솔은 의미만 렌더링한다. FS-006·057 선행; P2 조회 기반, E2 사양 관리 확장.
- **코드동작확인 Test방식:** Prototype 고정 목록, 미허용 참조, 회원 변경 거부, 중복 revision, 동시 편집 충돌, 개정 후 기존 VM의 고정 revision을 확인한다. DB 이력과 신청 시 선택된 정의가 소급 변경되지 않아야 한다.
- **코드동작확인 로깅방식:** 감사에 행위자·profile 참조·revision·변경 속성 종류·허용/거부를 기록한다. 내부 주소·직접 자원값은 공개 로그에서 제외 또는 필요한 범위로 마스킹한다. 신청 당시 참조·revision·감사 행을 대조한다.
- **완료·반환 증거:** 고정 목록·권한 차단·변경 이력 불변식과 경합 판정의 실제 Test 증거를 반환한다. 실제 자원 수치는 G1 전 미확정으로 남긴다.

## FS-011 관리자 회원 관리

<a id="fs-011"></a>
### FS-011 관리자 회원 관리

- **목적:** 확정된 필드와 역할 정책 안에서 관리자가 시험 회원을 안전하게 조회·관리한다.
- **추가 범위:** 관리자 전용 목록/상세·허용 변경 사용 사례 및 변경 이력 조회.
- **수정 범위:** Identity 관리 계약은 기존 인증 계정 변경과 역할 부여 권한을 분리하고 변경 가능 필드를 명시적으로 제한한다.
- **삭제 범위:** 회원 본인의 관리자 관리 API 접근, 암묵적 관리자 승격, 인증정보 조회·로그 노출을 허용하지 않는다.
- **goal:** 허용된 계정 정보만 관리하고 중복 식별·잘못된 역할·동시 변경은 안전하게 거부한다.
- **non-goal:** 변경 필드가 확정되기 전 임의 프로필·비밀번호 초기화·삭제/비활성화 정책을 만들지 않는다.
- **목표-input:** `actor_context`는 API가 확인한 관리자 문맥, `member_ref`는 Identity 내부 회원 식별, `member_changes`는 사전 승인된 필드 의미와 기대 revision이며 관리자 콘솔이 제공한다.
- **목표-output:** `member_view`는 허용된 계정 정보만 담아 관리자 콘솔에 반환, `management_result`는 성공/거부/충돌, `account_history`는 변경자·시각·필드 종류·전후 의미의 안전한 감사 참조다.
- **구현 동작:** 관리자 권한과 필드 allowlist를 검증하고 불변 식별자·중복 로그인 식별·금지 역할 전이를 확인한다. 계정 변경과 revision/감사 기록은 한 트랜잭션에서 수행하고 동시 편집은 기대 revision이 낡으면 충돌 처리한다. 자격 증명 변경 정책이 확정된 경우에도 원문을 조회/응답하지 않고 별도 검증된 경로를 사용한다. 실패 시 상태는 그대로 두고 타인 미존재/조회 제한은 정책에 맞춰 최소 정보 응답한다.
- **책임·의존 계약:** Identity가 계정/그룹·변경 이력을 소유하고 Audit는 관리 사건을 기록, 관리자 콘솔은 API만 호출한다. 필드·역할 변경 정책 확정 및 FS-006·057 선행; E2 적용.
- **코드동작확인 Test방식:** 관리자 정상 변경, 회원 접근, 중복 식별, 잘못된 역할, 허용되지 않은 필드, 동시 revision 편집을 확인한다. DB 전후 상태·이력·API 응답이 합치고 비밀정보가 나오지 않아야 한다.
- **코드동작확인 로깅방식:** 감사에 관리자/대상 참조·필드 종류·결과·revision만 기록한다. 개인정보 전체·자격 증명은 제외한다. 감사 행·DB 변화·관리 화면의 변경 이력을 같은 추적으로 대조한다.
- **완료·반환 증거:** 확정 필드 계약, 관리자 경로/회원 거부, 변경 이력·동시성 Test 결과 및 남은 정책 항목을 반환한다.

## FS-035 가상 단가·반올림 버전 관리

<a id="fs-035"></a>
### FS-035 가상 단가·반올림 버전 관리

- **목적:** 청구 계산에 적용된 규칙을 버전으로 고정해 과거 결과를 재현한다.
- **추가 범위:** E3 규칙 등록·검증·선택 기능, Decimal 계산 의미와 불변 revision.
- **수정 범위:** Billing은 VM 사양 사용 구간과 규칙 버전을 연결하고 청구서마다 사용한 규칙 참조를 고정한다.
- **삭제 범위:** 이미 발행된 청구에 현재 규칙을 재적용하거나 부동소수점으로 금액을 누적하지 않는다.
- **goal:** 기간·단위·반올림 정책이 유효한 규칙만 계산에 사용하고 과거 버전이 보존된다.
- **non-goal:** 실제 판매 단가, 세금·통화·결제 정책을 미확정 상태에서 만들거나 실금전 청구를 수행하지 않는다.
- **목표-input:** `pricing_definition`은 정책 담당자가 공급하는 사양별 가상 요율·과금 단위 의미, `rounding_policy`는 반올림 시점/방법/단위 의미, `effective_period`는 적용 경계, `policy_authority`는 관리자 권한 문맥이다.
- **목표-output:** `pricing_version`은 불변 규칙 revision 참조, `validated_rules`는 Billing 계산기가 받아 쓸 수 있는 검증 규칙, `policy_errors`는 겹침·단위 불일치·누락 의미의 거부 사유다.
- **구현 동작:** 권한·정의 스키마·기간 경계·정밀도/반올림 정책이 정해졌는지 검증한다. 등록 시 동일 사양·경계의 충돌을 잠금 또는 serializable한 고유 규칙 검사로 차단하고 불변 버전과 감사를 한 트랜잭션에 기록한다. 계산기는 명시적 버전 참조와 Decimal만 받아 사용하며 암묵적 최신 규칙 선택을 금지한다. 저장 실패·동시 충돌이면 전체 변경을 롤백하고 기존 청구 결과는 유지한다. 세금 등 미결 정책이 계산 결과에 필수면 발행을 보류한다.
- **책임·의존 계약:** Billing이 요율 정의·유효 구간·계산기 규칙을 소유, Vm은 사양 참조만 제공, 관리 주체는 정책을 승인한다. 청구 정책 결정·FS-036과 FS-057 필요; E3.
- **코드동작확인 Test방식:** 기간 시작/종료 경계·겹침 동시 등록·잘못된 단위·정밀도·반올림 순서·새 revision 이후 과거 청구 재현을 확인한다. Decimal 중간/최종 결과, 청구 버전 참조와 감사 이력이 일치해야 한다.
- **코드동작확인 로깅방식:** 감사에 규칙 버전·정책 기간 의미·변경자·판정; 기술 로그에 계산기 버전·선택된 참조·거부 분류를 기록한다. 직접 단가를 공개하지 않고 계산 Test의 정제 입력/기대 결과와 DB revision을 대조한다.
- **완료·반환 증거:** 확정된 규칙 스키마와 경계/재현 Test 결과, 규칙 revision 및 청구 연결 증거를 반환한다. 정책 미확정이면 보류 항목을 명시한다.

## FS-036 실제 적용 사양별 사용 구간

<a id="fs-036"></a>
### FS-036 실제 적용 사양별 사용 구간

- **목적:** 확인된 VM 생명주기와 적용 사양 변경을 기준으로 겹치거나 빠지지 않는 청구 대상 사용 구간을 만든다.
- **추가 범위:** 확정 이벤트를 구간 경계로 변환하는 Billing 원장과 재처리 규칙.
- **수정 범위:** Vm은 실제 적용 확정 사양 이력을 Billing에 불변 참조로 제공한다.
- **삭제 범위:** 요청 제출 시각을 실제 적용 시각으로 간주하거나 조회 관찰만으로 청구 확정하지 않는다.
- **goal:** 생성/삭제/사양 변경의 확인 시각으로 월별 구간을 산출하고 불완전 근거는 발행 차단 대상으로 둔다.
- **non-goal:** 중지 시간 과금 여부나 과금 시간 단위/최소 단위 등 미확정 정책을 추정하지 않는다.
- **목표-input:** `verified_lifecycle`은 Jobs/Vm이 제공하는 확인된 생성·삭제 사건과 관찰 시각, `applied_spec_history`는 실제 반영이 확정된 사양 및 유효 시각, `period_context`는 UTC 원장과 승인된 Asia/Seoul 월 경계 규칙이다.
- **목표-output:** `usage_segments`는 Billing이 계산 단계로 전달하는 사양 연결 사용 구간, `segment_boundaries`는 구간별 근거 사건과 양끝 의미, `incomplete_evidence`는 부족/충돌 근거와 발행 보류 사유다.
- **구현 동작:** 수신 사건 ID·VM 참조·유효 시각·확정 상태를 검증하고 같은 VM의 기존 수명주기 이력과 순서를 검사한다. VM별 구간 갱신은 잠금/버전 조건 아래 중복 사건 고유 제약과 함께 처리하며, 사양 변경 순간에 이전 구간을 닫고 새 구간을 연다. 재전달된 사건은 동일 식별자면 기존 결과를 반환한다. 역순·충돌·삭제 후 사건은 자동으로 덮어쓰지 않고 재확인 대상으로 격리한다. UTC 경계를 저장하고 승인된 시간대 변환만 청구 월 분할에 사용한다. 원장·감사 저장 실패 시 사건 적용 전체를 롤백하며 불완전 VM은 발행 대상에서 제외/보류한다.
- **책임·의존 계약:** Vm/Jobs가 확인된 생명주기 사건의 원천, Billing이 사용 원장·구간화·보류를 소유한다. 단가·시간 경계 정책 결정, FS-015·034와 FS-035 선행; E3.
- **코드동작확인 Test방식:** 생성, 월 경계, 사양 변경, 중지/재개, 삭제, 역순·중복 사건, 동시 사건 처리를 고정 시각으로 시험한다. 중지 과금 포함 여부는 확정 정책 입력으로만 확인한다. 구간의 연속성·겹침 없음·누락 없음 및 사용 사양의 적용 이력 일치를 DB에서 관찰한다.
- **코드동작확인 로깅방식:** 기술 사건에 VM 참조·원천 이벤트·신규/재사용/보류·경계 시각 의미·규칙 revision을 기록하고 감사 원장과 구간 테이블을 대조한다. 내부 연결정보·개인식별을 배제한다.
- **완료·반환 증거:** 사건 순서/중복 재생/월 경계의 고정 시계 Test 결과, 정제 구간 원장과 원천 이력 대조, 미확정 과금 정책을 반환한다.

## FS-037 전월 청구서 발행·중복 방지

<a id="fs-037"></a>
### FS-037 전월 청구서 발행·중복 방지

- **목적:** 승인된 월 실행에서 완전한 사용 원장과 해당 규칙으로 회원별 청구서를 한 번만 발행한다.
- **추가 범위:** 명시적 기간 실행·계산 근거 항목·재실행 안전성·발행 결과 분류.
- **수정 범위:** Billing은 FS-036 구간과 FS-035 규칙을 고정 snapshot으로 연결하고 관리자 화면/CLI에 보류를 설명한다.
- **삭제 범위:** 누락 근거를 0으로 치환하거나 정기 실행 재시도에서 중복 청구를 만드는 처리를 금지한다.
- **goal:** 사용자 지역 월 경계에 맞는 전월 기간을 대상으로 완전한 자료만 한 번 발행하고 재실행 결과를 결정적으로 반환한다.
- **non-goal:** 실금전 청구·결제, 확정되지 않은 할인·세금·지급기한 정책을 만들지 않는다.
- **목표-input:** `billing_month`는 월별 실행기가 전달하는 대상 월 의미, `usage_segments`는 FS-036의 확정 구간, `pricing_versions`는 적용 규칙 참조, `run_context`는 정기/수동 재실행과 권한·추적 문맥이다.
- **목표-output:** `invoice_ref`는 회원·월 청구 식별, `line_items`는 구간/사양/규칙 참조와 계산 설명, `total_and_status`는 합계 및 초안/발행/보류 상태 의미, `issuance_resolution`은 신규/기존 멱등 반환/보류/충돌 판정이며 호출자에 전달된다.
- **구현 동작:** 대상 월·권한·규칙 버전·구간 완전성·계산 재현성을 검사한다. 회원별 청구·항목·합계·상태·감사를 한 DB 트랜잭션에 저장하고 회원/월 고유 제약으로 경합을 막는다. 청구 발행이 선정 알림 사건인 경우에만 동일 트랜잭션에 알림 outbox를 추가하며 실제 전달은 커밋 후 별도 소비자에게 맡긴다. 동시 충돌 후 동일 입력은 기존 참조, 다른 snapshot은 덮어쓰기 없이 충돌/보류다. 알림 사건이 미정이면 임의로 발송 기능을 켜지 않는다. 불완전한 근거는 발행 완료로 기록하지 않는다.
- **책임·의존 계약:** Billing이 청구 계산·원장·고유성 소유, 실행기는 명시 월/추적 ID만 공급하고 Notifications는 발행 후 별도 소비자다. FS-035·036·057과 청구 정책 확정 선행; E3.
- **코드동작확인 Test방식:** 월 경계, 사양 분할, 규칙 revision, 불완전 구간 보류, 같은 실행 재호출, 같은 회원/월 동시 실행, 다른 입력 충돌을 확인한다. DB 고유 행·항목 합계·구간×단가 근거와 외부 화면 합계가 일치하고 중복 invoice가 없어야 한다.
- **코드동작확인 로깅방식:** 발행/보류 감사 사건에 실행 참조·월·회원 내부 참조·구간/규칙 버전·결과를 남긴다. 기술 로그는 요약 분류·소요만 기록한다. 합계·항목을 Test 계산 및 저장 원장과 대조하며 개인 금액 상세는 증거에서 정제한다.
- **완료·반환 증거:** 단일/동시/재실행 결과와 원장 유일성, 계산 항목 대조, 보류 조건에 대한 실제 Test 기록을 반환한다.

## FS-038 청구서 조회·상태 관리

<a id="fs-038"></a>
### FS-038 청구서 조회·상태 관리

- **목적:** 소유권 범위의 가상 청구 근거를 설명하고 승인된 상태 전이만 기록한다.
- **추가 범위:** 회원/관리자 청구 목록·상세와 상태 변경 사용 사례, 감사 가능한 상태 이력.
- **수정 범위:** 청구 상세는 당시 구간·사양·규칙 버전 및 계산 근거를 읽기 전용으로 연결한다.
- **삭제 범위:** 결제사 결과가 없는 청구를 결제 완료로 표시하거나 허용되지 않은 상태를 직접 덮어쓰지 않는다.
- **goal:** 사용자 본인 또는 관리자 허용 범위에서 청구 내역과 상태·보류 이유를 일관되게 제공한다.
- **non-goal:** 테스트 PG가 미확정/미연결이면 결제 처리, 카드정보 수집, 금융상태를 암시하는 기능은 제공하지 않는다.
- **목표-input:** `actor_context`는 FS-006의 회원/관리자 문맥, `invoice_ref`는 청구 참조, `query_scope`는 허용 기간/상태/페이지 의미, `state_action`은 확정 상태 정책에 포함된 전이 의미다.
- **목표-output:** `invoice_view`는 기간·구간·사양·규칙 버전·계산·상태의 설명, `state_history`는 전이자·시각·근거 참조, `denial_or_pending`은 거부/미정 정책/PG 조건 대기 이유이며 API가 콘솔에 반환한다.
- **구현 동작:** 인증·소유 범위와 입력 조건을 검증한 뒤 청구·항목·버전 이력을 읽는다. 상태 변경은 허용 전이표와 기대 revision을 검사하고 상태·이력·감사를 한 트랜잭션에서 갱신하며 동시 요청은 revision 비교로 하나만 성공한다. 잘못된 전이·타인 참조는 변경 전에 거부한다. PG 결과 연결은 공식 테스트 환경 결정이 선행된 별도 adapter가 인증/중복 검증한 결과만 상태 사용 사례에 제공한다. 미확정이면 자체 확정 범위를 반환하고 청구 계산 이력을 불변으로 둔다.
- **책임·의존 계약:** Billing이 청구/상태/이력 소유, Identity는 권한 제공, 콘솔은 결과 표시. FS-006·035~037 선행; E3, PG 선택 시 FS-047/E4 결정과 분리.
- **코드동작확인 Test방식:** 회원 본인·관리자 전체·타인 404, 상세 근거, 불가 상태 전이, 동시 변경, PG 없이 사용 가능한 조회/상태를 확인한다. 화면의 합계·상태·원인이 원장·이력과 일치해야 한다.
- **코드동작확인 로깅방식:** 조회 기술 로그에는 참조/범위/결과, 변경 감사에는 행위자·청구 참조·전후 상태·근거를 남긴다. 카드·개인 결제정보는 금지한다. UI·API·청구 행·상태 이력을 같은 추적으로 대조한다.
- **완료·반환 증거:** 소유권/상태전이/PG 미연결 경계와 항목 근거 표시의 실행 Test, 정제 화면·원장 대조를 반환한다.

## FS-044 Slack 알림

<a id="fs-044"></a>
### FS-044 Slack 알림

- **목적:** E4에서 승인된 사건을 승인된 시험 목적지에 전달하고 발송 실패·중복을 추적한다.
- **추가 범위:** Notifications의 이벤트 수신, 정책 필터, outbox 전달 시도 원장, Slack adapter.
- **수정 범위:** 원천 업무 모듈은 커밋된 사건만 outbox로 제공하고 알림 결과는 원천 작업 성공/실패를 변경하지 않는다.
- **삭제 범위:** Prototype 외부 발송, 임의 채널 입력, 로그/증거에 webhook·토큰·메시지 본문을 남기는 동작을 금지한다.
- **goal:** 명시적으로 선정한 알림만 중복 통제와 제한 재시도로 전달하고 영구 실패를 보이게 한다.
- **non-goal:** 미정 알림 사건을 추정하거나 모든 제품 이벤트를 자동 공지하지 않는다.
- **목표-input:** `notification_event`는 Jobs/Infrastructure/Billing이 제공하는 정제 사건 의미와 고유 이벤트 참조, `destination_ref`는 비밀 없는 허용 목적지 별칭, `notification_policy`는 승인된 사건 종류·중복키·재시도/억제 조건이다.
- **목표-output:** `delivery_ref`는 발송 시도 식별, `delivery_result`는 접수/전달확인/실패/보류 구분, `retry_state`는 횟수·다음 조치의 의미이며 Notifications 원장과 운영자가 받는다.
- **구현 동작:** 내부 outbox의 발행자 신뢰 경계·schema·허용 사건·목적지·중복키를 확인한다. 내부 메시지 서명/HMAC 계약은 추가하지 않는다. worker가 짧은 DB 트랜잭션으로 점유·시도를 저장하고 커밋한 뒤 잠금 없이 외부 호출한다. 호출 결과는 별도 DB 트랜잭션으로 시도·전달 상태에 저장한다. 수락 후 응답 유실이면 전달 불명확으로 기록한다. 내부 중복키는 중복 시도 원장을 제어할 뿐 외부 exactly-once를 보장하지 않으며, 공급자의 중복 지원 확인 전 자동 재전송하지 않고 정책상 재확인/제한 재시도를 선택한다. E4에서 사건·목적지·재시도 정책을 정하고 알림 실패가 원천 업무 결과를 되돌리지 않게 한다.
- **책임·의존 계약:** Notifications가 전송·원장 소유, 원천 모듈은 outbox event 공급, 비밀 저장/운영자는 목적지 제공. E4에서 사건·중복 정책 선결정 후 적용.
- **코드동작확인 Test방식:** 허용 시험 목적지에서 정상·목적지 오류·외부 장애·같은 사건·worker 중단을 확인한다. 공급자 수락 후 응답 유실도 주입해 전달 불명확·중복 가능성·정책상 재확인을 확인하고, 내부 고유 원장만으로 외부 단일 수신을 주장하지 않는다. 원천 VM/청구 결과는 알림 실패와 분리한다.
- **코드동작확인 로깅방식:** `event_id`, `delivery_ref`, 시도, 결과 분류, 목적지 별칭, request/trace ID를 기술 로그와 발송 원장에 기록한다. webhook·토큰·전체 메시지는 제외한다. Slack 시험 수신 기록·원장·원천 상태를 대조한다.
- **완료·반환 증거:** 승인된 사건/목적지 결정, 허용 시험 수신 확인과 실패/중복/복구 Test의 정제 증거를 반환한다. 외부 발송은 승인된 E4 실습 조건 이후에만 실행한다.

## FS-045 제한 이메일 시험

<a id="fs-045"></a>
### FS-045 제한 이메일 시험

- **목적:** 승인된 임시 메일 환경과 허용 수신자 안에서 전달 경로를 시험한다.
- **추가 범위:** 수신자 allowlist 판정, 시험 환경 adapter, 접수와 실제 수신 확인의 별도 상태.
- **수정 범위:** Notifications 발송 worker가 사건을 정제 템플릿으로 변환하고 제한 환경으로만 전달한다.
- **삭제 범위:** 운영/임의 수신자로의 발송, 본문·주소·SMTP 비밀의 일반 로그 저장을 금지한다.
- **goal:** 비허용 수신자를 외부 호출 전에 차단하고 SMTP 접수와 사용자가 확인한 수신을 구분한다.
- **non-goal:** 마케팅 메일·광범위 공지·상시 운영 메일 서비스는 범위 밖이다.
- **목표-input:** `message_event`는 알림 사건의 정제 의미, `recipient_ref`는 허용 주소 목록에 대응하는 수신자 참조, `mail_test_environment`는 임시 서버·발송 제한의 검증된 설정 의미다. 이를 Notifications가 받는다.
- **목표-output:** `mail_attempt`는 발송 시도 ID, `mail_delivery_state`는 접수/배달 확인/실패/거부 구분, `recipient_validation`은 허용 판정이며 발송 원장과 시험 담당자에게 전달된다.
- **구현 동작:** 시험 환경·수신자 allowlist·사건을 검사해 비허용 수신은 외부 호출 전에 차단한다. worker는 점유·시도를 커밋한 뒤 DB 잠금 없이 SMTP 호출하고 별도 트랜잭션으로 응답/접수 상태를 기록한다. SMTP 접수·실제 mailbox 확인·전달 불명확을 구분한다. 내부 고유키는 원장/소비 중복만 제어하며 외부 메일 중복까지 보장하지 않는다. 수락 뒤 응답 유실과 worker 중단에서는 무조건 재발송하지 않고 선정 정책의 재확인/제한 재시도를 따른다. 원천 업무 결과는 변경하지 않는다.
- **책임·의존 계약:** Notifications가 정책·시도 원장·SMTP adapter를 소유하고 허용 수신자/임시 서버 운영자가 시험 조건을 공급한다. E4이며 발송 사건·수신 제한 선행 확정 필요.
- **코드동작확인 Test방식:** 허용/비허용 수신자·서버 장애·중복 사건·접수 후 미확인·수락 후 응답 유실을 검사한다. 거부 시 외부 호출 없음, 접수/수신/불명확의 분리, 내부 원장의 단일 처리와 외부 중복 가능성의 구분을 확인한다.
- **코드동작확인 로깅방식:** `delivery_ref`·수신자 별칭/해시 참조·검증 결과·접수/배달 확인·시도·오류를 기록한다. 주소·본문·비밀번호·전체 헤더는 제외한다. 임시 mailbox 증거·발송 원장·외부 접수 식별자를 대조한다.
- **완료·반환 증거:** allowlist 차단, 접수/실수신 구분, 장애/중복 Test의 정제 증거와 제한된 수신 환경 결정 근거를 반환한다.

## FS-046 SMS 시험 가능성·조건부 연동

<a id="fs-046"></a>
### FS-046 SMS 시험 가능성·조건부 연동

- **목적:** 공식 공급자의 시험 기능과 사용 조건을 확인하고 승인된 조건에서만 SMS 시험 범위를 정한다.
- **추가 범위:** 공식 근거에 기반한 가능성 판정 기록; 결정 후에만 SMS adapter·제한 발송 기록.
- **수정 범위:** Notifications가 미결정 상태를 `조건 대기`로 표시하며 발송 준비를 실행 경로에서 차단한다.
- **삭제 범위:** 공식 시험 수신·시험 자격이 확인되지 않은 발송, 실수신번호/개인번호에 대한 임의 전송을 금지한다.
- **goal:** 연동 여부·허용 수신 범위·시험/실발송 구분을 검토 가능한 근거로 결정하고 선택된 경우에만 제한 검증한다.
- **non-goal:** 현재 정보만으로 공급자, 가격, SMS 사건 또는 실제 발송을 확정하지 않는다.
- **목표-input:** `official_test_capability`는 공식 공급자 문서/계정 절차가 제공하는 시험 지원·제한·자격 근거, `allowed_recipient_policy`는 승인된 수신 범위, `implementation_decision`은 담당자 승인한 구현/보류 결정, 조건부 `notification_event`는 정제된 발송 의미다.
- **목표-output:** `sms_scope_decision`은 결정·근거·조건 대기 사유, 조건 충족 시 `sms_delivery_state`는 시도/성공확인/실패 의미이며 문서화와 Notifications 원장이 수신한다.
- **구현 동작:** 공식 문서와 계정에서 시험 가능성·인증·수신자·비용/실발송 전환 위험을 확인하고 검토 기록을 만든다. 필수 조건 또는 결정이 없으면 기능을 차단하고 조건 대기로 반환한다. 결정이 승인된 뒤에만 allowlist와 test mode를 검증하고 비동기 worker가 idempotency 키로 호출한다. 외부 호출 잠금은 DB 밖에서 수행하고 요청·응답 상태를 발송 원장에 기록하며 응답 모호성은 성공으로 추정하지 않고 재확인한다. 실패해도 원천 업무 결과에는 영향이 없다. 취소/실발송 경계는 공급자 공식 시험 규칙과 승인 정책으로 제한한다.
- **책임·의존 계약:** 운영/보안 담당이 공식 근거와 수신 정책을 승인, Notifications가 adapter·원장을 구현한다. 공식 가능성 및 명시적 결정 선행; E4 조건부.
- **코드동작확인 Test방식:** 미확보 조건에서 호출이 차단되는지, 시험 인증/허용 수신·정상·실패 분기를 선택된 공식 환경에서 확인한다. 시험 모드 식별자·외부 제공자 관찰·원장 상태가 일치하고 실발송으로 전환되지 않아야 한다.
- **코드동작확인 로깅방식:** 결정 근거 링크/버전·판정·수신자 참조·시도·결과를 기록한다. 전화번호·API 키·본문은 제외한다. 공식 시험 관찰값과 발송 원장·Test 결과를 연결한다.
- **완료·반환 증거:** 공식 자료 기반 결정 기록 또는 보류 증거를 반환한다. 연동 선택 후에는 시험/실발송 경계가 검증된 정제 증거를 추가한다.

## FS-047 테스트 PG 가능성·조건부 연동

<a id="fs-047"></a>
### FS-047 테스트 PG 가능성·조건부 연동

- **목적:** 공식 PG 시험 환경의 전제 조건을 판정하고 승인된 시험 결과만 가상 청구 상태와 연결한다.
- **추가 범위:** 공식 시험 가능성 결정 기록; 승인 시에 한해 시험 주문/결과 연결과 취소·실패 처리 adapter.
- **수정 범위:** Billing 청구 상태 흐름은 외부 시험 결과를 별도 참조로 기록하고 원래 계산 원장을 불변으로 보존한다.
- **삭제 범위:** 실제 결제 호출, 카드 정보 수집, 인증되지 않은 브라우저 반환 URL만으로 결제 성공 확정은 금지한다.
- **goal:** 공식 시험 자격·중복결과·청구 연결이 모두 검증된 경우 시험 상태를 정확한 invoice에만 반영한다.
- **non-goal:** 시험 PG를 필수로 전제하거나 미확정이면 FS-038 자체 상태 관리 범위를 확장하지 않는다.
- **목표-input:** `official_pg_test_capability`는 공식 PG 문서/계정의 시험 자격·환경·웹훅 규칙 근거, `test_invoice_ref`는 Billing 청구 참조, `test_payment_context`는 시험 주문·콜백/결과와 청구 간 관계, `implementation_decision`은 연동 또는 자체 상태 관리의 승인 결정이다.
- **목표-output:** `pg_scope_decision`은 구현/보류/대체 범위와 근거, 조건부 `test_payment_result`는 시험 처리·취소·실패와 검증된 청구 참조, 처리결과다.
- **구현 동작:** 선정된 공식 공급자의 시험 지원·자격·실결제 차단·결과 확인·중복/취소 계약을 확인한다. 미충족이면 PG 경로를 비활성화하고 FS-038을 유지한다. 시험 청구와 거래/시도 관계를 서버에서 연결하고 공급자 계약이 요구하는 인증·재생 방지·거래 식별 수단만 적용한다. 서명·nonce·웹훅을 미리 필수로 정하지 않으며 실패/취소 뒤 재시도 관계도 선정 계약으로 결정한다. 검증 결과·청구 상태/이력·감사를 한 트랜잭션에 반영해 반복은 멱등 처리하고 충돌/다른 청구 연결은 격리한다. 외부 호출은 잠금 밖에서 수행하며 불명확 결과는 재확인으로 둔다. 계산 원장은 시험 결과로 바꾸지 않는다.
- **책임·의존 계약:** 공식 근거와 결정은 결제/보안 담당, Billing이 invoice 상태와 관계를 소유, Integrations가 PG protocol 변환을 담당한다. FS-035~038 및 E4 공식 시험 조건·명시 결정 선행; 조건부.
- **코드동작확인 Test방식:** 자격 미확보 차단, 중복 결과, 실패/취소, 다른 청구 연결, 결과 인증 실패, 결과 저장 중 장애와 재처리를 확인한다. 승인된 시험 제공자 상태·청구 참조·거래 고유성·감사 전이가 일치하고 실결제 자격/경로는 사용되지 않아야 한다.
- **코드동작확인 로깅방식:** 결정 근거·시험환경 식별·invoice 내부 참조·정제 거래 참조·중복/상태 결과를 감사/기술 기록에 남긴다. 카드/개인정보·결제 키·서명 원문은 기록하지 않는다. 공식 시험 콘솔 관찰·inbox·Billing 상태 이력을 대조한다.
- **완료·반환 증거:** 공식 시험 지원 판정 또는 보류, 승인 시 각 실패/중복/격리·재처리 Test 결과와 청구 이력 대조를 반환한다.

## FS-058 콘솔 API 프록시·신뢰 헤더

<a id="fs-058"></a>
### FS-058 콘솔 API 프록시·신뢰 헤더

- **목적:** 고객·관리자 콘솔의 동일 출처 `/api/` 경로를 API로 안전하게 전달하고 전달 헤더 위조를 막는다.
- **추가 범위:** 허용 경로/메서드 중계 정책, 신뢰 proxy 판정, Host·scheme·request ID 정규화와 쿠키 응답 전달 규칙.
- **수정 범위:** 콘솔 웹 경로와 API 수신 경계는 등록된 proxy만 신뢰하며 API에서 사용자가 보낸 인증/신뢰 헤더를 제거 또는 거부한다.
- **삭제 범위:** 임의 Host·외부 직접 API 호출·사용자 제공 forwarded/authentication 헤더로 신원이나 보안 scheme을 바꾸는 처리를 금지한다.
- **goal:** 두 콘솔의 같은 출처 인증·CSRF 요청이 정해진 API 경로로 전달되고 콘솔별 쿠키 경계가 유지된다.
- **non-goal:** Prototype에서 공개 DNS나 사설망 실습 주소를 임의 확정하거나 proxy가 인증/권한을 대신 판정하지 않는다.
- **목표-input:** `browser_request`는 등록 콘솔에서 온 경로·메서드·세션/CSRF 문맥, `proxy_routes`는 콘솔 운영자가 등록한 API 경로 관계, `trusted_proxy_policy`는 중계 주체와 Host/scheme/request ID 처리 의미다.
- **목표-output:** `forwarded_request`는 정규화된 API 요청과 검증 중계 문맥, `browser_response`는 API 결과 및 해당 콘솔 보안 쿠키 속성, `routing_rejection`은 미등록 경로/위조 문맥 거부를 프록시/API가 반환한다.
- **구현 동작:** 콘솔 웹서버에서 허용된 `/api/` prefix·메서드만 매칭하고 원래 브라우저의 위조 가능한 Forwarded/X-Forwarded/Auth 헤더를 제거한 뒤 등록된 Host/scheme·요청 ID를 설정한다. API는 연결 출처가 허용 proxy인지 확인한 후에만 해당 정규화 헤더를 신뢰하고, 인증은 별도로 Shield 세션에서 수행한다. proxy 전달은 요청 본문·상태·필요 응답 헤더를 보존하되 hop-by-hop 헤더를 제외하고 Set-Cookie는 해당 console host-only 정책에 맞춘다. Host/경로 검사 실패는 upstream 호출 전 거부한다. API timeout은 안전한 오류로 끝나며 재시도해 변경을 중복 실행하지 않는다. Prototype HTTP 예외는 loopback 전용, 실습은 HTTPS와 등록 사설 DNS 조건 확인 후 적용한다.
- **책임·의존 계약:** 콘솔 웹 경로가 라우팅·정규화, API가 proxy 신뢰 목록·세션 인증을 소유한다. 네트워크 계층/운영 설정은 환경 제공자가 검증한다. G0 이후 P1, FS-004·005에 선행.
- **코드동작확인 Test방식:** 두 콘솔 로그인/API 호출·세션/CSRF 쿠키 경계, 미등록 Host·경로, 위조 Forwarded/Auth 헤더, 직접 API 접근, 잘못된 scheme을 요청해 결과를 확인한다. 허용 요청은 API 로그와 일치하고 거부 요청은 upstream 업무 처리/DB 변경이 없어야 한다.
- **코드동작확인 로깅방식:** 접근/기술 로그에 콘솔 역할·정규화 경로·요청 ID·신뢰 판정·결과만 남긴다. 쿠키·비밀 헤더·query string·본문은 제외한다. proxy 접근 로그·API 추적·브라우저 결과를 같은 ID로 대조한다.
- **완료·반환 증거:** proxy 경로/헤더 신뢰 표, 정상·위조·직접 접근 Test 결과, 두 콘솔의 정제된 브라우저/API 로그 대조를 반환한다.
