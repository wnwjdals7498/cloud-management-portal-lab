# 병렬 구현의 작업 묶음·계약·통합

> [상세계획 안내](README.md), [기능목록](../feature-list.md), [기능 명세](../function-specification.md)를 기준으로 한다. 이번 요청의 산출물은 구현계획이다. 실제 코드·환경 설치·인프라 실행은 이후 구현 작업에서 수행한다.

## 작업 인계 단위

‘로그인 동작을 신뢰할 수 있게 제공한다’, ‘중복 요청의 업무 효과가 한 번만 반영된다’처럼 관찰 가능한 책임을 인계한다. 구현자는 승인된 모듈 경계 안에서 클래스·함수·배치를 정한다. 특정 파일의 편집 여부는 완료 조건이 아니다.

한 묶음은 아래 내용을 자체 완결로 제공한다. 담당 기능의 상세계획은 근거로 연결하되 링크만 던지고 작업 의미를 생략하지 않는다.

- **목적·상황:** 어떤 요청/사건에서 어떤 문제를 해결하는가.
- **추가/수정/삭제범위:** 만들 책임, 변경할 수 있는 계약, 제거/배제할 동작. 기존 코드가 없는 단계에서는 추가 구현과 미래 변경 경계를 구분한다.
- **goal:** 사용자/외부 관찰·원장·상태의 합격 불변식. **non-goal:** 이 묶음이 넘겨야 할 다른 책임과 보류 정책.
- **input/output:** 의미·공급자/수신자·필수/옵션·실패/보류를 정의한다. 직접 값·비밀·주소·예제 JSON을 인계에 넣지 않는다.
- **동작·실패:** 검증, 지속 저장, 외부 효과, 반영, 중단 후 회복의 순서. 트랜잭션·잠금·멱등·시도 번호를 포함한다.
- **소유·의존:** 단일 변경 주체와 사용할 계약, 준비된 선행 증거. 선행 기능을 임의 재구현하지 않는다.
- **Test·로그:** 확인할 정상/거부/경계/실패/동시성/재기동과 관찰값, 정제 로그·원장·외부 증거의 연결.
- **반환:** 완료한 책임·변경된 계약·실제 Test 결과·증거·실행하지 않은 항목·남은 의존.

## 공유 계약의 소유

아래 이름은 책임을 설명하는 논리 계약이다. 새 wire wrapper·전역 이벤트 버스·추가 서비스 도입을 뜻하지 않는다. 구체 타입/schema는 P0에서 원문 계약에 맞춰 합의·버전 고정한다.

| 계약 | 의미 | 단일 소유 책임 | 소비 책임 |
| --- | --- | --- | --- |
| 인증 문맥 | 서버가 확인한 행위자·역할·세션/서비스 종류·환경 | Identity; 서비스 인증 정책은 보안 운영 | Vm·Jobs·Billing·Infrastructure·콘솔 API |
| 사양 스냅샷 | 신청 당시 허용 사양·버전·가용 상태·제약 | Vm 사양 관리 | 신청·변경·사용 구간 계산 |
| 제출 식별·해결 | 행위자·작업종류·키·본문 일치 관계와 신규/기존/충돌 판정 | Jobs 신청/멱등 | 신청 API·worker |
| 작업 명령·접수 | 허용 동작·서버 대상·시도·외부 멱등 관계·접수/불명확 의미 | Jobs·Gateway 경계 | 모의/실제 수신부 |

| 기술 추적 | 환경·release·요청/작업/시도·사건·오류·소요와 정제 정책 | Logging | 모든 모듈·worker·dispatcher |
| 원장 구조 변경 | 테이블 책임·외래키·고유 제약·버전·호환 조건 | 각 업무 모듈은 제안 소유, migration 적용은 통합 담당 | 설치·각 모듈·배포 |
| 가상 계산 규칙 | 단가·단위·반올림·적용 기간·불변 버전 의미 | Billing | 사용 구간·청구 발행 |
| 정제 알림 명령 | 선정 사건·목적지 참조·중복/재시도 의미 | Notifications | Jobs·Infrastructure·감시 |
| 운영/검증 증거 | 실제 환경·검사·관찰·판정·한계·정제 자료 연결 | 해당 검증 담당; 전체 기능 대응은 통합 담당 | 단계 완료·기능 보고 |

공유 계약 변경은 제안 → 영향 기능/소비자 확인 → 통합 담당 확정 → 소유자의 단일 반영 → 계약 Test 순서다. 다른 담당자는 자기 편의로 상태 값·식별 의미·오류 분류·공통 라우팅·의존성·schema를 바꾸지 않는다.

## 트랜잭션과 변경 경계

- 신청의 Vm·Jobs·outbox·Audit는 동일 업무 트랜잭션으로 커밋한다. 하위 사양 조회·감사 제공자는 호출자의 트랜잭션을 따르며 독립 커밋하지 않는다.
- 큐 점유/회수·시도 갱신은 짧은 트랜잭션과 유효 lease로 보호한다. 네트워크 호출은 DB 잠금 밖에서 수행하고 응답 저장 시 lease·시도·현재 상태를 다시 검사한다. 소유권을 잃은 worker가 최신 결과를 덮어쓰지 못하게 한다.
- 완료 수신은 신원/schema 검증 후 inbox에 지속 저장한다. 선행 통지는 매핑을 기다리고, 적용 시 사건 고유 제약·시도·현재 상태 검사를 업무 반영과 함께 처리한다. 응답 ACK와 처리 결과의 의미를 계약으로 구분한다.
- 상태의 최종 변경 책임은 Jobs다. Receiver·StatusReader·콘솔·모의 수신부가 업무 상태를 직접 덮어쓰지 않는다. Vm 실제 적용값 반영은 Vm 사용 사례로, Audit 추가는 Audit 계약으로 수행한다.
- callback 누락·접수 불명확·기한 초과는 재확인으로 남긴다. 조회만으로 완료 확정하거나 외부 멱등 확인 없이 생성 명령을 반복하지 않는다.
- Billing은 확정된 VM 사건만 소비한다. 내부 모듈 호출은 DTO/메서드로, 후속 실행이 필요한 사건은 기존 outbox 경계로 전달한다. 소비 완료는 불변 사건/구간의 중복 제약으로 확인한다.
- 모의 DB/schema·권한·ID 소속은 업무 DB와 분리한다. 업무 DB 구조 제안은 모듈별로 수집하지만 migration 버전·순서·실행은 통합 담당이 직렬 적용한다.

## 구현 착수와 병렬 순서

상세계획 작성은 모든 영역을 병렬 진행할 수 있다. 실제 구현은 아래 선행 계약·환경·Test 증거가 있어야 시작한다. 준비되지 않은 계약은 명시적 stub/독립 fixture로 단위 확인할 수 있지만 종단 구현 완료로 보고하지 않는다.

## 코드 작업의 변경 소유·통합

- 에이전트마다 맡은 기능·모듈/계약 소유를 선언하고, 남의 소유 범위는 변경 제안만 전달한다. 파일 목록을 인계 목표로 사용하지 않는다.
- 공통 routes·서비스 조립·의존성 잠금·migration·schema·공유 UI 규칙은 통합 담당의 단일 작성 영역이다. 각 담당은 필요한 의미와 영향 소비자를 반환한다.
- 기능 내부의 단위/계약 Test를 먼저 수행하고, 통합 담당이 schema/조립 적용 → 통합 Test → 종단 Test → 증거 점검 순서로 연결한다.
- 계약 불일치·미정 게이트가 발견되면 그 경계의 코드 착수/통합을 보류하고 독립 가능한 책임만 진행한다. 추정값으로 gate/Test를 통과시키지 않는다.
- 실습 VM·운영 서비스·배포·복원·인증서 교체처럼 외부 상태를 바꾸는 작업은 동일 대상/환경에 한 실행자만 둔다. 백업·중단/복구 조건을 확인하고 원문의 승인 범위를 따른다.
- PMT 점유·결정·기록·검증·종료는 주 에이전트만 관리한다. 서브에이전트는 자기 산출물·Test 근거를 반환한다.

## 에이전트 반환 계약

| 반환 항목 | 의미 |
| --- | --- |
| 기능·책임 | 완료한 기능 ID와 관찰 가능한 동작 |
| 계약 영향 | 입력/출력/오류/상태·schema·버전의 변경 의미와 소비자 |
| 변경 범위 | 추가/수정/삭제한 책임과 배제한 동작. 파일 diff는 부속 증거 |
| Test | 실제 수행 방법·관찰·판정·미실행/조건 대기 이유 |
| 로깅 | 사건/추적·Audit/기술 경계·정제 확인·상태와 대조 결과 |
| 증거 | 재현 조건·release·mode·정제 자료 참조·확인 한계 |
| 통합 요청 | 필요한 공통 조립/schema·선행 기능·충돌과 대안 |

주 에이전트는 기능 대응·계약·증거를 확인한 뒤 완료한다. 문서 작성 성공, 단위 Test 성공, 모의 종단 성공, 실제 실습 성공, 운영 합격을 각각 구분한다.
