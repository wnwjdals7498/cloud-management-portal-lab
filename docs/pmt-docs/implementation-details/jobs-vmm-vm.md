# 작업·모의 VMM·실제 VM 기능별 구현 상세계획

[상세계획 안내](README.md) · [기능 명세](../function-specification.md) · [원문 계획](../../implementation-plan-v1.md) · [공유 계약·통합](parallel-execution.md).

기준은 기능목록·기능명세, 1차 구현계획의 작업/통신·모의 규칙, 계약 및 VMM 모의 연동이다. 최초 작성은 구현 전 계획이며 Prototype 범위는 P2~P3의 신청·작업·모의 통지다. 이후 구현 결과는 [검증 기록](../../operations/prototype-progress.md)을 따른다. 실제 adapter·VM 기능은 각 E 게이트 통과 후 조건부로 진행한다. 제안 설정값은 확정값으로 간주하지 않는다.

## FS-012~020 신청·작업·통지

### FS-012 VM 생성 신청·작업 등록
<a id="fs-012"></a>
- **목적:** 권한 있는 사용자의 생성 의도를 중복 없이 접수하고 비동기 실행 준비 상태를 명확히 반환한다.
- **추가 범위:** Vm 소유·논리 식별, Jobs 작업/최초 시도, outbox 전달 의도, Audit 접수 결과를 단일 원자적 업무로 구성한다.
- **수정 범위:** FS-004~006의 인증·권한·오류 계약 및 FS-010 사양 선택을 호출 경계로 적용한다. 접수는 완료 의미가 아니다.
- **삭제 범위:** 해당 없음. 코드가 없는 계획 단계이므로 제거할 기존 동작은 없다.
- **goal:** 허용 사양·신청자 한도·환경을 확인한 뒤 VM·작업·outbox·감사를 전부 저장하거나 전부 취소한다.
- **non-goal:** 승인 흐름, 실제 자원 예약, 생성 완료를 접수 시점에 표시하는 것.
- **목표-input:** profile 참조는 사양 조회가 공급, actor/권한·할당량 문맥은 인증·정책 경계가 공급, 멱등 식별과 요청 내용은 콘솔이 공급, mode는 서버 설정이 공급한다.
- **목표-output:** job·논리 VM·request 추적 참조와 접수 상태를 콘솔에 반환하며, 지속 원장은 worker와 운영 확인이 소비한다.
- **구현 동작:** 인증·CSRF·권한·정적 입력 검증 → 멱등 해석으로 기존 요청을 먼저 반환하거나 내용 충돌 거부 → 신규 요청만 업무 트랜잭션에서 사양 revision·가용 상태와 신청자 한도를 다시 검사한다. 한도 판정은 신청자별 잠금 또는 원자 예약으로 보호하며, 서로 다른 키의 동시 신청도 같은 잔여 한도를 중복 소비하지 못하게 한다. 한도 예약·논리 VM·job/최초 attempt·outbox·Audit를 함께 커밋/롤백하고 커밋 뒤 접수를 반환한다. DB 장애/중단 후 같은 제출은 최초 원장에 연결하며 변경된 한도 때문에 기존 접수가 새 거부로 바뀌지 않는다.
- **책임·의존 계약:** Vm은 사양·소유권·논리 VM 규칙, Jobs는 작업·시도·outbox 생성, Audit는 행위 기록을 소유한다. API 유스케이스가 이들을 한 DB 트랜잭션으로 조정한다. 외부 효과는 outbox 소비자만 수행한다.
- **코드동작확인 Test방식:** 정상 신청에서 한도 예약·VM/job/outbox/audit 참조를 대조한다. 동일 키 동시 제출은 원 작업에 연결하고, 서로 다른 키의 한도 경합은 확정 한도를 초과 수용하지 않아야 한다. 접수 후 한도/사양 가용성 변경에서도 같은 내용의 재전송은 최초 결과를 반환한다. 각 저장 단계 장애에서는 예약까지 롤백되고 잘못된 사양·권한·내용 충돌은 외부 효과 없이 거부된다.
- **코드동작확인 로깅방식:** 접수·거부 사건에 request/job/VM 참조, actor 분류, profile 참조, mode, 이유 코드를 남긴다. 요청 본문·키 원문·비밀은 제외한다. 로그의 접수와 DB 상태를 대조해 생성 성공으로 오인되지 않게 한다.
- **완료·반환 증거:** 유스케이스 입력/출력 계약, 정상·거부·롤백·동시성 결과, DB의 VM/job/outbox/audit 일관성, 정제된 추적 기록 및 미확인 의존 항목.

### FS-013 요청 중복 방지
<a id="fs-013"></a>
- **목적:** 재전송이 새 작업·VM·외부 실행을 만들지 않도록 제출 의도를 안정적으로 해석한다.
- **추가 범위:** 행위자·작업 종류·키의 유일성, 정규화 내용 지문, 최초 작업 연결, 충돌 분류.
- **수정 범위:** FS-012 신청 경로는 신규/기존/충돌 결과를 동일 응답 계약으로 다룬다.
- **삭제 범위:** 키를 메모리에서만 기억하거나 재전송마다 신규 처리하는 동작을 허용하지 않는다.
- **goal:** 동일 scope·키·내용이면 원 작업 참조를 반환하고, 내용이 다르면 충돌을 반환한다.
- **non-goal:** 멱등 기록 만료 정책을 임의 결정하거나 명시적 재시도를 기존 요청으로 위장하는 것.
- **목표-input:** 요청 식별은 인증 주체·작업 유스케이스·클라이언트 키에서 구성하고, 지문은 서버의 정규화된 허용 업무 필드에서 만든다. 최초 요청은 저장소가 공급한다.
- **목표-output:** 신규 생성 허가, 기존 job/VM 연결 또는 충돌 사유를 신청 유스케이스에 전달한다.
- **구현 동작:** 키 형식/범위와 입력 정규화 → 같은 업무 트랜잭션에서 고유 제약으로 선점 및 지문 저장 → 충돌 경합 시 기존 행 재조회 → 지문 일치면 기존 결과, 불일치면 conflict. 경합자 모두가 중복 원장을 만들지 않는다. 명시적 retry는 권한 검사 후 새 attempt 정책으로 분리한다.
- **책임·의존 계약:** Jobs/Persistence가 고유성·지문 비교를 책임지고 신청 API가 결과를 번역한다. 외부 gateway는 내부 키와 안정적으로 연결된 동일 외부 멱등 키를 받는다.
- **코드동작확인 Test방식:** 순차·동시 동일 제출, 같은 키의 내용 변경, 다른 actor/작업 종류의 같은 키를 비교한다. 기존 작업 재사용에서는 VM/outbox/외부 접수 횟수가 증가하지 않고, 충돌은 영향이 없어야 한다.
- **코드동작확인 로깅방식:** 신규·재사용·충돌 사건 및 원 작업 참조/지문 비교 결과만 기록한다. 키 원문과 본문은 마스킹/제외한다. 고유 제약·원장·외부 시도와 사건 수를 대조한다.
- **완료·반환 증거:** 유일성 scope와 지문 정규화 규칙, 경합·충돌 관찰, 단일 외부 효과 증거, 보존/만료가 미정이면 명시한 보류.

### FS-014 outbox 점유·외부 전달
<a id="fs-014"></a>
- **목적:** 저장된 실행 의도를 worker 중단과 경합에도 안전하게 외부에 전달한다.
- **추가 범위:** 원자적 lease 획득/만료/회수, dispatch attempt 이력, 결과 분류와 외부 참조 저장.
- **수정 범위:** Jobs 상태 전이 및 Gateway 추상 계약을 연결하고 P에서는 모의 adapter를 선택한다.
- **삭제 범위:** DB 트랜잭션을 네트워크 왕복 동안 열어 두는 흐름, lease 없는 점유를 배제한다.
- **goal:** 유효 lease 소유자만 호출하며 응답 유실은 불명확으로 저장하고 안전한 재연결을 가능하게 한다.
- **non-goal:** 외부 결과가 불명확한데 새 멱등 식별자로 생성 요청을 재발행하는 것.
- **목표-input:** outbox는 Jobs가 공급, lease 정책은 설정이 공급, gateway는 mode 조립부가 공급하며 attempt·외부 멱등 식별은 지속 원장에서 파생한다.
- **목표-output:** 접수·거부·불명확 분류, 외부 작업 참조, lease/attempt 결과를 Jobs·복구 흐름에 돌려준다.
- **구현 동작:** 짧은 DB 트랜잭션에서 점유·lease token/만료·attempt 시작 저장 후 커밋 → 네트워크 호출(잠금 없음) → 별도 트랜잭션에서 lease token과 현재 attempt 재검증 후 결과 저장/전이. 접수 응답 유실·시간 초과는 재확인으로 남기고 기존 접수를 먼저 조회한다. 같은 키의 재접수는 선택 수신부가 해당 멱등 계약을 실제 제공·검증한 경우에만 허용한다. 미확인 실제 수신부에는 새 생성 호출을 보내지 않는다. lease 회수는 이전 worker의 DB 후발 저장을 차단하지만 이미 진행 중인 외부 효과를 취소하거나 단일 효과를 보장하는 수단은 아니다.
- **책임·의존 계약:** Jobs worker가 점유·시도·DB 반영을, Gateway가 변환·호출을 소유한다. 모의 수신부의 멱등 효과는 FS-022~023에서 검증한다. 실제 외부 중복 방지는 수신부의 키 저장·조회·재접수 계약 확인이 선행하며 키를 보내는 것만으로 보장하지 않는다.
- **코드동작확인 Test방식:** 여러 worker 경합에서 한 유효 lease, 느린 gateway 중 DB 잠금 미보유, 응답 유실, lease 만료 후 옛 worker 응답, 재기동 후 동일 키 재확인을 검사한다. DB 이력과 모의/외부 수신 횟수를 대조한다.
- **코드동작확인 로깅방식:** lease 획득/거부/회수, 호출 시작/접수/불명확, duration, worker·job·attempt 추적을 기록한다. 주소·명령·본문·키 원문은 제외한다. 외부 접수와 attempt 원장을 함께 대조한다.
- **완료·반환 증거:** lease 불변식, 잠금 해제 시점, 유실/늦은 응답 처리 결과, 동일 외부 멱등 식별 추적 및 worker 재기동 관찰.

### FS-015 작업 상태 전이·결과 반영
<a id="fs-015"></a>
- **목적:** 검증 근거와 현재 attempt에 맞는 결과만 작업·VM 원장에 확정한다.
- **추가 범위:** 전이 규칙, 조건부 갱신, 결과 근거와 감사의 원자 반영, VM 관찰 상태와 작업 상태 분리.
- **수정 범위:** callback/inbox, gateway receipt, reconciliation 입력을 단일 전이 정책에 연결한다.
- **삭제 범위:** 접수만으로 succeeded 처리, 오래된 관찰값으로 확정 결과 덮어쓰기, 전원/게스트 상태를 작업 상태로 혼합하는 동작.
- **goal:** 합법 전이만 원자적으로 적용하고 늦은 유효 완료를 검증한 뒤 확정 가능하게 한다.
- **non-goal:** 외부 근거 없이 VM 전원이나 게스트 상태를 추론하는 것.
- **목표-input:** 상태 저장소가 현재 job/attempt를, 통지 검증기가 사건 근거를, Vm/StatusReader가 관찰값과 시각을 공급한다.
- **목표-output:** 적용·보류·거부된 전이와 작업/VM 참조, 감사 결과를 소비자에게 반환한다.
- **구현 동작:** job·attempt 잠금/버전 확인 → 사건 ID·mode·대상·attempt 검증 → 전이표 및 terminal 상태 검사 → 작업 결과, 허용된 VM 메타데이터/관찰 반영, 감사 및 inbox 처리 결과를 하나의 업무 트랜잭션으로 저장. 중복은 no-op, stale attempt·상충 terminal 사건은 격리한다. 늦은 사건은 유효성·현재 불변식 확인 후에만 반영한다.
- **책임·의존 계약:** Jobs가 작업 상태 정책을 소유하고 Vm 유스케이스가 VM 정보 갱신을 소유한다. 감사와 상태 변경은 같은 트랜잭션. 모듈은 내부 DTO/유스케이스 계약으로 통신한다.
- **코드동작확인 Test방식:** 허용/금지 전이, receipt-only, 중복, 늦은 유효 완료, 이전 attempt, terminal conflict, 트랜잭션 장애를 검사한다. job·VM·audit/inbox 처리의 원자성과 전원·게스트·작업 필드 분리를 본다.
- **코드동작확인 로깅방식:** 이전/이후 상태, 원인 사건·attempt·대상 참조, 적용/보류/격리 사유를 기술 로그와 감사에 구분해 기록한다. 로그 사건과 조건부 DB 변경을 대조한다.
- **완료·반환 증거:** 전이표·상태 불변식, 사례별 DB 스냅샷 비교, stale/terminal 격리 근거, 작업/전원/게스트 구별 결과.

### FS-016 완료 통지 인증·수신 검증
<a id="fs-016"></a>
- **목적:** 신뢰된 서비스가 보낸 계약에 부합하는 완료 사건만 지속 수신한다.
- **추가 범위:** 송신자 인증·출발지/환경 확인, schema 및 식별자 검증, inbox 수신 원장.
- **수정 범위:** 통지 수신 endpoint는 사용자 세션 경로와 분리하고 개발 loopback 허용은 환경 검증에 묶는다.
- **삭제 범위:** 수신 단계에서 미검증 통지로 업무 상태를 직접 변경하는 동작.
- **goal:** 허용 통지는 durable inbox에 한 번 저장하고 이후 처리 가능하게 응답한다.
- **non-goal:** 확정된 상호 TLS를 다른 인증수단으로 바꾸거나 메시지 HMAC/서명을 새 필수로 추가하는 것. 실제 IIS 기술·인증서 신원 매핑·계정·주소를 G1 전에 추정하지 않는다.
- **목표-input:** 서비스 신원은 TLS/허용 출발지 경계가, 메시지는 VMM 송신부가, job/외부 ID 매핑은 Jobs 원장이 공급한다.
- **목표-output:** 허용/거부 분류, inbox 참조, 검증 오류 범주를 송신부와 내부 처리기에 반환한다.
- **구현 동작:** mode/환경 허용성 및 송신 신원 확인 → 크기/형식/schema 검증 → 필수 식별·관찰·결과·시도·대상·mode 간 일치성 검사 → event 고유 키로 inbox 저장 → 저장 성공 후 수신 확인. 인증/계약 오류는 업무 반영 전 거부한다. 외부 매핑 미존재는 유효 통지라면 보류 표식으로 저장하고 재처리한다. 중단 후 inbox에서 재개한다.
- **책임·의존 계약:** CompletionReceiver가 인증·계약 경계를, Jobs가 inbox 소유와 연계를 담당한다. 실제 경로의 상호 TLS·등록 출발지 제한은 이미 확정이다. G1에서는 IIS 기술·클라이언트 신원 매핑·인증서/CA·계정·허용 출발지의 적합성과 연결 동작을 확인한다.
- **코드동작확인 Test방식:** 유효 통지, 잘못된 인증·schema·대상·mode·attempt, 외부 ID 매핑 선행/후행, inbox 저장 장애와 중복 event를 확인한다. 모든 부적격 통지에서 업무 원장이 변하지 않아야 한다.
- **코드동작확인 로깅방식:** 수신/거부, 송신 service 역할, job/event 참조, 검사 범주를 남긴다. 비밀·인증 자료·전체 본문은 기록하지 않는다. 수신 확인 응답은 inbox 지속성 증거와 대조한다.
- **완료·반환 증거:** 인증 및 수신 계약, 검증 거부표, durable inbox 중복/재기동 결과, G1 의존성 목록.

### FS-017 선행·중복·충돌 통지 처리
<a id="fs-017"></a>
- **목적:** 순서 뒤바뀜과 재전송이 업무 효과를 중복시키거나 확정 결과를 훼손하지 않게 한다.
- **추가 범위:** event 유일성·정규화한 계약 내용의 일치 판정 정보, 처리 lease/상태, 매핑 대기, 동일 ID의 내용 충돌·stale attempt·terminal 충돌 격리.
- **수정 범위:** FS-015 상태 반영을 통한 단일 업무효과와 inbox 처리 결과 기록.
- **삭제 범위:** inbox 조회 후 매번 감사/VM 변경을 적용하는 비멱등 처리.
- **goal:** 동일 event는 단일 효과, 매핑 전 통지는 대기, 충돌은 격리·감사한다.
- **non-goal:** 통지 도착 순서를 외부 실행 순서의 진실로 간주하는 것.
- **목표-input:** 지속 inbox event, event identity, 외부 ID 매핑 준비 상태, current attempt/terminal 결과를 Jobs 원장이 제공한다.
- **목표-output:** applied/deferred/duplicate/isolated 처리 결과와 실제 반영 여부를 worker 및 감사 조회에 제공한다.
- **구현 동작:** 인증/schema가 검증된 통지를 최초 저장할 때 계약 필드의 정규화 내용 일치 정보를 보존한다. 같은 event ID·같은 내용은 멱등 재전송, 같은 ID·다른 내용은 프로토콜 충돌로 격리·감사하고 업무를 바꾸지 않는다. 이는 메시지 서명이나 인증의 대체가 아니다. inbox 점유 뒤 외부 매핑을 확인해 부족하면 보류하고, 현재 attempt·대상·환경을 대조한다. 조건부 Jobs 전이·Vm 반영·Audit·inbox 처리 결과를 한 트랜잭션으로 커밋한다. 기존 성공 효과는 반복하지 않고 stale/terminal 충돌은 격리한다. ACK는 지속 수신/동일 중복/충돌을 구분하며 중단 후 원장으로 재개한다.
- **책임·의존 계약:** inbox 소비자는 Jobs, 실제 VM 정보 갱신은 Vm, 감사는 Audit 소유. event 고유 제약과 처리 lease가 동시 소비를 막는다.
- **코드동작확인 Test방식:** 외부 ID 등록 전후, 같은 ID·같은 내용의 순차/동시 재전송, 같은 ID·다른 내용, 이전 attempt, terminal 충돌, 처리 중 재기동을 주입한다. 정상 사건의 단일 업무 효과와 내용 충돌의 업무 무변경·격리/감사, ACK 구분, 매핑 후 재개를 검증한다.
- **코드동작확인 로깅방식:** deferred/retry/duplicate/isolated/applied 사건, event/job/attempt 참조, 사유 코드를 기록한다. inbox 상태·감사 건수·VM/job 최종 원장을 대조한다.
- **완료·반환 증거:** event identity 규칙, 순서/중복/충돌 시나리오의 단일 효과 증거, 재기동 복구 및 격리 기록.

### FS-018 외부 상태 관찰·동기화 조회
<a id="fs-018"></a>
- **목적:** 작업 또는 VM의 외부 관찰값과 최신성·불일치를 분리해 조회자에게 제공한다.
- **추가 범위:** 모의/실제 StatusReader 경계, 관찰 원장, 조회 오류와 freshness 표현.
- **수정 범위:** 화면/API 조회는 확정 업무상태와 외부 관찰값을 별도 필드로 전달한다.
- **삭제 범위:** 외부 조회 결과를 검증 없이 확정 원장으로 덮어쓰기, 누락을 조회만으로 성공 처리하는 동작.
- **goal:** 최신 관찰 및 관찰 시각을 제시하고 실패 시 마지막 관찰의 오래됨을 표시한다.
- **non-goal:** MSSQL 조회 대상·권한·실제 구현을 G1 이전에 결정하거나 외부 상태를 성공의 단독 증거로 쓰는 것.
- **목표-input:** 인증된 job/VM 참조는 API가, reader 구현/mode는 조립부가, 마지막 관찰은 관찰 저장소가 공급한다.
- **목표-output:** 관찰값·시각·freshness·확정 결과와의 차이를 API 소비자에 반환한다.
- **구현 동작:** 권한/소유권 및 대상 확인 → 설정된 연결 한도 안에서 StatusReader 호출(세션/DB 잠금 해제) → 응답 schema·mode·대상 검증 → 관찰값과 시각을 제한된 transaction으로 저장 → 확정 원장과 차이를 계산해 표시. 실패/timeout은 이전 관찰을 stale 표식과 함께 반환하고 재확인 대상으로 둔다.
- **책임·의존 계약:** Integrations StatusReader는 외부 변환·조회, Jobs/Vm은 관찰 참조와 확정 상태, API는 응답 모델을 책임진다. MSSQL 및 권한 계약은 G1 의존이다.
- **코드동작확인 Test방식:** 정상·빈/오류 응답·연결/권한 실패·병렬 조회·callback 불일치·오래된 관찰을 검사한다. 조회만으로 작업 terminal 변경이 없고 모의/실제 adapter 경계가 유지되는지 본다.
- **코드동작확인 로깅방식:** adapter 종류, 대상 참조, 관찰 시각, 소요, freshness/불일치·오류 코드를 기록한다. SQL 원문·주소·자격증명은 남기지 않고 API·관찰 원장·callback을 대조한다.
- **완료·반환 증거:** reader 계약, 성공/실패/불일치 출력과 원장 대조, G1 MSSQL 결정을 위한 미확인 사항.

### FS-019 지연·누락 재확인·명시적 재시도
<a id="fs-019"></a>
- **목적:** 지연·누락·응답 유실을 불명확 상태로 보존하고 근거에 맞는 복구만 허용한다.
- **추가 범위:** reconciliation 이유/다음 확인 조건, 권한 감사, retry attempt 분리 및 위험 차단.
- **수정 범위:** worker·운영자가 같은 외부 작업 확인과 callback 재처리를 요청할 수 있도록 Jobs 복구 계약을 적용한다.
- **삭제 범위:** 시간 경과만으로 failed/succeeded 확정, 접수 불명확 상태에서 다른 키로 자동 재생성.
- **goal:** 조회·재통지·새 attempt를 분류하며 새 시도에는 권한·근거·별도 이력을 요구한다.
- **non-goal:** 실제 VMM 재시도/취소/보상 정책을 E1 결정 전에 정하는 것.
- **목표-input:** job·deadline 의미·외부 receipt/observation은 저장소 및 StatusReader가, recovery action과 actor는 권한 있는 운영 경계가 공급한다.
- **목표-output:** reconciliation 상태, 확인 근거, retry attempt 또는 action guard를 화면/worker에 반환한다.
- **구현 동작:** 대상·역할·현재 상태 검사 → 불명확 원인과 최초 외부 멱등 식별 확인 → 조회/기존 요청 재연결/통지 재처리 중 허용된 행동 수행 → 결과 근거를 저장. 누락 조회는 관찰만 갱신하고 terminal 성공을 확정하지 않는다. 신규 attempt는 별도 승인/감사·식별을 생성하고 실제 외부 멱등 계약 미확인 시 생성 재시도 차단. 늦은 유효 완료는 attempt/대상 검증 후 FS-015가 확정한다.
- **책임·의존 계약:** Jobs가 reconciliation·retry 정책을, Integrations가 조회/동일 외부 키 재연결을, Audit가 운영 행위를 소유한다. 미정 recovery 정책은 E1 게이트다.
- **코드동작확인 Test방식:** 접수 응답 유실, 늦은 완료, 통지 누락, 재통지 중복, 조회 실패, 새 attempt 권한 거부를 확인한다. 읽기만으로 성공이 되지 않고 미확인 계약에서 재생성이 차단되는지 검사한다.
- **코드동작확인 로깅방식:** 행위자·job·action·근거·시도·결과·guard 사유를 감사하고 기술 로그에는 대기/재확인 사건을 남긴다. 외부 관찰·요청 이력·원장 상태를 상호 대조한다.
- **완료·반환 증거:** 복구 결정표, 차단/허용 경계, 늦은 완료 확인, 실제 복구 정책이 남긴 E1 보류 사항.

### FS-020 worker 중단·재기동 복구
<a id="fs-020"></a>
- **목적:** 프로세스 종료 시점에 관계없이 지속 원장을 기준으로 안전하게 작업을 이어간다.
- **추가 범위:** lease 만료 회수, 미완료 inbox/outbox 재발견, 외부 receipt 재연결, 잔여 불명확 상태 보고.
- **수정 범위:** dispatcher의 시작 시점 및 반복 주기는 저장 상태에서 복구되도록 구성한다.
- **삭제 범위:** 메모리 큐가 유일한 작업 원천인 처리.
- **goal:** lease fencing과 idempotent 처리로 유실 없이 재개하고 외부 중복 효과를 억제한다.
- **non-goal:** 불명확 상태를 자동 실패 처리하거나 미검증 운영 원복을 실행하는 것.
- **목표-input:** outbox/inbox/attempt 원장과 lease는 DB가, 외부 receipt는 Gateway/StatusReader가, 재기동 문맥은 worker runtime이 공급한다.
- **목표-output:** 회수/재연결된 작업과 남은 unknown, 복구 결과를 운영 관찰에 제공한다.
- **구현 동작:** worker 시작 시 만료 lease·미완료 행을 찾아 짧은 트랜잭션으로 점유한다. 기존 외부 receipt/키 조회를 우선하고 미확정은 재확인 상태로 보존한다. 실제 수신부의 멱등 재접수 지원이 검증되지 않았다면 응답 유실·lease 만료 뒤 생성 호출을 자동 반복하지 않는다. inbox는 지속 처리 상태와 내용 일치 정보를 확인해 재개하며 기존 업무 효과를 반복하지 않는다. 외부 조회/호출 중 DB 잠금은 유지하지 않는다.
- **책임·의존 계약:** Jobs worker가 recovery 스캔·점유, Gateway가 접수 재연결, inbox 처리기가 통지 복구를 소유한다. 저장소가 정합 기준이며 프로세스 메모리는 캐시일 뿐이다.
- **코드동작확인 Test방식:** 점유 직후, 외부 접수 후 응답 저장 전, inbox 적용 전 프로세스를 끊고 재기동한다. 유효 lease 만료 전 중복 점유 불가, 만료 후 fencing, 동일 외부 작업 연결, 효과 단일 반영, unknown 보존을 확인한다.
- **코드동작확인 로깅방식:** 시작·회수·receipt 재연결·보류 사건과 job/attempt/lease 참조를 기록한다. 비밀·주소를 제외하고 전후 DB 원장과 외부/모의 대상 수를 대조한다.
- **완료·반환 증거:** 각 장애 지점의 전후 상태·회수 결과, 재기동 중복 방지 증거, 남은 unknown과 복구 제한.

## FS-021~024 모의 VMM

### FS-021 모의 응답 범위 설정 검증
<a id="fs-021"></a>
- **목적:** 모의 실행 전에 설정이 허용된 시나리오와 실행 경계를 만족함을 보장한다.
- **추가 범위:** profile schema/version, 가중치·범위·오류 allowlist·지연·중복·대기량 정책 검증.
- **수정 범위:** 모의 앱 기동 및 요청 경로는 검증된 불변 profile만 받는다.
- **삭제 범위:** 잘못됐거나 부분적으로 적용된 profile로 추첨·전송을 시작하는 동작.
- **goal:** 검증 실패 시 기동/요청을 닫고 어느 항목이 유효하지 않은지 식별한다.
- **non-goal:** 미확정 기본 수치나 운영 용량 한도를 확정하는 것.
- **목표-input:** profile과 버전·seed 정책은 환경 설정 공급자가 제공한다.
- **목표-output:** 불변 validated profile 또는 오류 집합과 시작 허용 결정을 dispatcher 및 simulator에 전달한다.
- **구현 동작:** schema·필수값·형식 → 가중치 합/부호, 지연 순서, 오류 allowlist, 대기·중복 상한 상호 검증 → 전체 검증 성공 시에만 profile snapshot 활성화. 부분 적용 금지. 버전 변경은 이후 요청에만 적용되며 기존 추첨 기록은 보존한다.
- **책임·의존 계약:** Simulator 설정 경계가 유효성 책임, dispatcher는 유효 profile 없이는 시작 불가. 수치는 1차 계획 제안이며 설정 원천에 귀속한다.
- **코드동작확인 Test방식:** 유효 설정과 누락/음수/불일치/범위 역전/미허용 오류/상한 초과/경계값을 검사한다. 잘못된 구성에서 추첨·예정 통지·요청 수락이 발생하지 않음을 본다.
- **코드동작확인 로깅방식:** profile 버전, 검사항목과 시작 결정만 기록한다. 비밀 설정은 제외한다. 기동 결과와 추첨/전송 원장 부재를 대조한다.
- **완료·반환 증거:** schema와 검증 불변식, 거부 사례 결과, 유효 profile 식별·기동 로그.

### FS-022 무작위 추첨·저장·재현
<a id="fs-022"></a>
- **목적:** 각 신규 유효 모의 요청의 실행 변수를 정확히 한 번 결정해 후속 조회·재시작에서 재사용한다.
- **추가 범위:** seed, 난수 알고리즘 버전, profile 버전, 입력 식별, 선택 시나리오/변수/due 시각의 지속 기록.
- **수정 범위:** 재접수는 FS-013 결과로 원 작업을 반환하고 추첨 경계를 재진입하지 않는다.
- **삭제 범위:** 조회·중복·재시작 때 새 난수 추첨을 수행하는 동작.
- **goal:** 결정 당시 입력·seed·알고리즘·profile 연결을 보존해 동일 요청의 추첨 결과를 재현·감사할 수 있게 한다.
- **non-goal:** 단일 추첨의 통계적 분포로 확률 적합성을 입증하는 것.
- **목표-input:** simulator 요청 식별·허용 작업 입력은 접수부가, validated profile은 FS-021이, seed와 알고리즘 식별은 설정/난수 공급자가 제공한다.
- **목표-output:** 저장된 scenario·지연/오류/전달 규칙과 추첨 기록 참조를 dispatcher·status reader에 제공한다.
- **구현 동작:** 유효 신규 요청 식별 → 트랜잭션/유일 제약으로 해당 요청의 추첨 슬롯 확보 → 정해진 알고리즘·입력·profile로 1회 결정 → 입력 fingerprint, seed 참조, 알고리즘/profile 버전, 결과 및 예정 시각을 모의 DB에 저장 → 커밋 후 접수 반환. 동시 중복 경합은 저장된 한 결과를 사용한다. 장애 후 기록이 없을 때만 재시도 가능한 원자 경계에서 결정하며 이미 저장된 결과는 덮어쓰지 않는다.
- **책임·의존 계약:** Simulator가 추첨과 모의 원장을 소유한다. API 업무 DB는 수정하지 않는다. 알고리즘/profile 버전은 추적 가능해야 하며 저장 입력은 민감정보를 최소화/정규화한다.
- **코드동작확인 Test방식:** profile 경계·시나리오 허용, 동일 seed 문맥 재현, 중복/조회/재시작 재사용, 동시 요청 단일 추첨을 확인한다. 결과와 seed/알고리즘/profile 연결 원장을 비교한다.
- **코드동작확인 로깅방식:** 추첨 신규/재사용 사건과 draw 참조를 남기고 seed 노출 정책은 보안 설정을 따른다. 상세 원장은 simulator DB에서 검증하고 로그 참조와 결합한다.
- **완료·반환 증거:** 결정 입력·버전·결과 연결성, 재현 사례, 동시/재시작 단일 추첨 증거.

### FS-023 모의 상태 저장·예정 통지 실행
<a id="fs-023"></a>
- **목적:** 추첨된 경로에 따른 가상 상태 변화를 지속하고 due 된 통지를 별도 dispatcher가 수행한다.
- **추가 범위:** simulator 전용 job/VM/delivery 상태, due 작업 점유 및 전송 이력.
- **수정 범위:** API inbox 계약에 맞춘 완료 통지 전송과 StatusReader 응답 매핑.
- **삭제 범위:** HTTP 요청에서 sleep하거나 simulator가 API 업무 테이블을 직접 쓰는 동작.
- **goal:** 지연·재시작·경합을 견디며 상태와 전송 결과를 별도 모의 저장소에 유지한다.
- **non-goal:** 실제 VM/네트워크 접속 정보를 만들거나 실환경 상태를 가장하는 것.
- **목표-input:** draw record는 FS-022가, simulator 상태는 전용 저장소가, 수신 대상 계약은 CompletionReceiver가 제공한다.
- **목표-output:** 작업/VM 관찰값과 due/delivery 상태, 계약에 맞춘 completion 메시지를 StatusReader·API 수신부에 전달한다.
- **구현 동작:** 요청 접수 시 상태·예정 delivery 지속 저장 → dispatcher가 due 행을 lease로 점유 → 잠금 해제 후 통지 전송 → 결과를 별도 기록하고 재시도/중복 정책 적용. 요청 처리 경로는 즉시 응답한다. dispatcher 재시작은 저장된 예정 상태부터 재개하며 대기 한도 초과는 거부/관찰 가능 오류로 처리한다.
- **책임·의존 계약:** Simulator DB는 sim job/VM/delivery만 소유하고 API DB 접근 권한은 갖지 않는다. dispatcher와 상태 reader는 simulator 계약을 통해서만 사용한다.
- **코드동작확인 Test방식:** 주입 clock으로 due 전후, dispatcher 경합·재시작, 전송 실패, 대기량 경계와 inbox 연계를 확인한다. HTTP 응답이 지연 대기하지 않고 업무 DB에 직접 변경이 없는지 검사한다.
- **코드동작확인 로깅방식:** 상태 생성·due 점유·전송·재시도 사건과 sim job/event 참조, 소요·결과를 기록한다. 민감 본문·주소를 마스킹하고 simulator delivery와 API inbox를 대조한다.
- **완료·반환 증거:** 지속 상태 전이, dispatcher 재기동/경합 및 지연 경계, API inbox 연계 증거.

### FS-024 성공·실패·지연·누락·중복 시나리오
<a id="fs-024"></a>
- **목적:** 지원하는 다섯 결과 흐름을 결정적으로 확인하고 운영 강제 실행을 차단한다.
- **추가 범위:** 개발 전용 시나리오 강제 입력, 기대 타임라인과 관찰 연결, 누락/지연/중복의 명확한 결과 분류.
- **수정 범위:** simulator 추첨은 일반 경로, 개발 CLI는 승인된 개발 환경에서만 강제 경로를 선택한다.
- **삭제 범위:** Production에서 강제 시나리오 또는 모의 adapter 실행을 허용하는 동작.
- **goal:** 정상·실패·늦은 완료·통지 누락·동일 사건 중복 전송을 각각 재현하며 각 효과를 단일하게 반영한다.
- **non-goal:** 테스트 편의를 위해 보안/인증 검사를 건너뛰거나 누락을 성공으로 치환하는 것.
- **목표-input:** scenario 선택은 저장된 추첨 또는 제한된 개발 CLI가, profile은 FS-021이, 검증 clock/기대 흐름은 테스트 계약이 공급한다.
- **목표-output:** 결과 효과·재현 참조·관찰 타임라인을 테스트와 운영 조회에 전달한다.
- **구현 동작:** 환경/mode 검사 → 강제 요청이면 개발 전용 권한·설정 확인 → 추첨/저장 불변식 유지 → 선택한 시나리오의 due state/delivery 규칙 실행. 누락은 상태 관찰만 남기고 reconciliation 유지, 늦은 유효 callback은 검증 후 확정, 중복은 같은 event identity로 전송해 단일 효과를 검증한다. Production이면 시나리오 강제 및 모의 실행을 기동/요청 단계에서 거부한다.
- **책임·의존 계약:** Simulator scenario runner와 개발 CLI가 분기 선택, Jobs가 callback 효과, 환경 조립부가 Production 차단을 책임진다. 기대 흐름은 구현과 독립된 계약 자료여야 한다.
- **코드동작확인 Test방식:** 각 다섯 흐름의 입력·기대 시각·조회·callback·DB 결과를 계약 기준으로 비교한다. 누락 조회 성공 금지, 늦은 완료 검증, 중복 단일 반영, 운영 강제 차단을 포함한다.
- **코드동작확인 로깅방식:** scenario 및 draw 참조, 발생/누락/재전송 event, 결과 분류를 기록한다. 기대·관찰 타임라인과 API DB, simulator DB, inbox/audit를 대조한다.
- **완료·반환 증거:** 다섯 흐름별 실행 흔적·DB 차이·로그 추적, 운영 차단 결과, 계약 불일치 목록.

## FS-028~034 실제 VMM·VM (E 게이트 이후)

### FS-028 실제 VMM 요청·결과 adapter
<a id="fs-028"></a>
- **목적:** 승인된 실제 환경에서 VM 작업 계약을 실제 VMM 프로토콜에 안전하게 매핑한다.
- **추가 범위:** Real Gateway 및 결과 mapping, 인증서/송신자 검증, 외부 접수 참조·오류 표준화.
- **수정 범위:** 설정 조립부가 G1 통과 후에만 실제 adapter를 허용한다. 공통 Jobs 계약은 보존한다.
- **삭제 범위:** 모의 ID/상태가 실제 adapter 경계를 통과하거나 Production에서 simulator 선택되는 경로.
- **goal:** 생성·운영 명령과 결과를 추적 가능한 방식으로 매핑하고 동일 외부 멱등 키·재연결 계약을 지킨다.
- **non-goal:** G1 전 실제 통신/자원 변경; 확인되지 않은 IIS 요청 규격·MSSQL 구조·VMM 명령이나 보상 정책의 추정 구현.
- **목표-input:** 표준 command/attempt/mode는 Jobs/Vm 유스케이스가, 승인된 endpoint/schema/신뢰 신원/멱등 의미는 G1 산출 계약이 공급한다.
- **목표-output:** 접수·실패·불명확·완료 결과와 외부 참조를 Jobs에 표준 형태로 반환한다.
- **구현 동작:** 기동 시 실제 환경·확정 mTLS 신원/체인·등록 출발지·권한을 확인한다. Jobs가 준비·점유한 허용 명령만 받고 adapter는 잠금/트랜잭션 없이 외부 호출을 수행한다. 응답을 검증·정규화해 Jobs에 돌려주면 Jobs가 현재 시도/lease를 재검사해 외부 참조·상태를 저장한다. timeout/연결 종료는 미접수로 단정하지 않는다. 같은 키 조회/재연결을 우선하고 수신부의 멱등 재접수가 확인되지 않았다면 생성 재호출을 차단한다. adapter 자체가 Jobs 상태를 쓰거나 새 attempt를 만들지 않는다.
- **책임·의존 계약:** adapter는 protocol 변환만, 준비/시도/트랜잭션/전이는 Vm·Jobs만 담당한다. API↔VMM의 상호 TLS·출발지 제한 원칙은 유지한다. G1에서는 실제 신원/인증서/권한 적합성, 요청/응답·외부 멱등 저장/조회·receipt 계약을 확인한다.
- **코드동작확인 Test방식:** 승인된 계약 fixture/격리 환경에서 정상 접수, 거부, 응답 유실, 잘못된 인증/응답, 중복 호출·재연결을 관찰한다. 실제 endpoint 정보 없이 모의 계약 테스트와 실환경 검증을 구분한다.
- **코드동작확인 로깅방식:** adapter·job·attempt·요청 추적·duration·응답 분류만 기록한다. 인증서 비밀/명령 본문/주소는 제거한다. VMM 접수 이력과 내부 attempt를 대조한다.
- **완료·반환 증거:** G1 결정된 protocol/신뢰/멱등 계약, 격리된 검증 결과, 접수 불명확 복구 결과 및 미구현 경계.

### FS-029 실제 VM 부팅·SSH 접근 확인
<a id="fs-029"></a>
- **목적:** E1 검증 범위에서 실제 VM이 부팅하고 승인된 접근 경로가 동작하는지 증거를 남긴다.
- **추가 범위:** 생성 완료와 별도의 guest readiness/접근 검증 절차 및 관찰 기록.
- **수정 범위:** VM 상세는 VMM 작업 결과와 게스트 관찰을 구분해 표현한다.
- **삭제 범위:** 모의 VM을 실제 SSH 대상처럼 표시하거나 작업 succeeded를 guest readiness와 동일시하는 것.
- **goal:** 승인된 테스트 VM에 대해 부팅·SSH 검증 여부와 시각·근거를 추적한다.
- **non-goal:** 실제 주소/계정/접속 자료를 문서화하거나 미확정 네트워크·이미지·접근 정책을 정하는 것.
- **목표-input:** 외부 VM 참조는 FS-028 결과가, 검증 대상·접근 정책·안전한 검사 방법은 G1과 운영자가 제공한다.
- **목표-output:** readiness/접근 결과, 관찰 시각·오류 분류를 검증 절차 및 허용 UI에 제공한다.
- **구현 동작:** 실환경/mode·대상 소유 확인 → 운영 승인된 안전 검사 준비 → VMM 상태와 게스트 접속 증거를 각각 수집 → 결과·시각·정제 참조 기록. 실패는 작업 결과를 덮지 않고 readiness 실패/미확인으로 남긴다. 재시도는 정책에 따라 감사한다.
- **책임·의존 계약:** Vm은 readiness 관찰을 보유하고 FS-028은 VMM 작업 결과만 제공한다. 접속 자격·주소는 보안 저장소/운영 경계가 소유한다.
- **코드동작확인 Test방식:** 부팅 성공/지연, SSH 성공/거부/경로 실패, VMM 성공 후 guest 미준비, 재검증을 각기 분리한다. 민감 접근 정보가 출력·로그·증거에 포함되지 않는지 확인한다.
- **코드동작확인 로깅방식:** 검증 주체·VM 참조·검사 종류·결과 분류·시각만 기록하고 인증정보와 내부 주소를 제거한다. VMM 상태와 guest evidence를 별도 대조한다.
- **완료·반환 증거:** E1 실환경 승인 범위, 안전한 부팅/접근 결과, 작업·전원·guest readiness 분리 근거와 미해결 환경 결정.

### FS-030 VM 시작
<a id="fs-030"></a>
- **목적:** 소유자가 허용된 VM 시작 명령을 비동기로 요청하고 검증 근거에 따라 결과를 관찰한다.
- **추가 범위:** 시작 command 정책, 작업/outbox/감사, VMM 결과 및 실제 전원 상태 관찰.
- **수정 범위:** VM 명령 공통 Jobs 계약과 API 권한 검사를 적용한다.
- **삭제 범위:** 요청 접수만으로 전원 on을 확정하거나 guest 준비를 추론하는 동작.
- **goal:** 권한·상태·동시 명령 규칙을 검증하고 작업 상태와 전원 관찰을 분리한다.
- **non-goal:** G1 이전 실제 start 명령 또는 재시도·동시 명령 우선순위 임의 결정.
- **목표-input:** 대상 VM과 소유권은 Vm, 요청 actor는 Identity, mode/실제 command capability는 설정 및 G1 계약이 공급한다.
- **목표-output:** job 접수 참조와 이후 관찰된 전원 상태·시각을 UI/작업 조회에 제공한다.
- **구현 동작:** actor/소유권/mode → VM 상태·진행 중 상충 명령 확인 → idempotency 적용 → 하나의 업무 transaction으로 job/outbox/audit 생성 → worker lease 및 외부 호출 잠금 분리 → 유효 callback/관찰 반영. 접수 불명확은 reconciliation, 전원 상태는 검증된 외부 관찰로 갱신한다.
- **책임·의존 계약:** Vm이 command 허용 조건과 전원 관찰, Jobs가 실행·멱등, Integrations가 adapter를 소유한다. 실제 수용 상태 전이는 G1 확인 대상으로 둔다.
- **코드동작확인 Test방식:** 허용 VM, 타인 VM, 이미 켜짐/상충 작업, 동시 시작, 응답 유실, 늦은 상태 관찰을 검사한다. 거부 감사와 작업/전원 상태 분리를 대조한다.
- **코드동작확인 로깅방식:** 요청/거부/dispatch/관찰 사건에 VM/job/attempt 참조 및 전원 관찰 시각을 기록한다. 명령 세부값·주소·비밀 없이 내부 원장과 VMM 결과를 대조한다.
- **완료·반환 증거:** 명령 전제 계약, 중복·충돌 결과, 전원 관찰의 외부 근거와 상태 분리, G1 이후 검증 증거.

### FS-031 VM 중지
<a id="fs-031"></a>
- **목적:** 권한 있는 중지 요청을 추적하며 요청 결과와 실제 전원/guest 상태를 별도로 보존한다.
- **추가 범위:** 중지 작업 유형, 거부·접수·불명확·완료 이력과 실제 관찰.
- **수정 범위:** 공통 command gateway와 audit/transition 계약.
- **삭제 범위:** 강제 종료 의미, 디스크·guest 안전정책을 근거 없이 적용하는 동작.
- **goal:** 승인된 중지 의미가 확정되기 전에는 graceful/force 정책을 구별하고 실제 결과만 관찰한다.
- **non-goal:** 사용자 확인 없는 강제 종료·자동 정리 또는 원복 정책 확정.
- **목표-input:** VM·현재 관찰·진행 중 작업은 Vm/Jobs, 허용 가능한 중지 의미 및 VMM 계약은 G1 결정이 제공한다.
- **목표-output:** 접수 작업과 확인된 전원/guest 결과 및 미확정 사유를 사용자/운영 화면에 전달한다.
- **구현 동작:** 권한·소유권·현재 상태·동시 명령 검사 → 요청된 중지 동작이 확정된 allowlist에 있는지 검증 → job/outbox/audit 단일 트랜잭션 → lease 기반 외부 호출(잠금 해제) → callback/StatusReader 근거를 검증해 전이. 접수/조회값만으로 중지 완료 확정하지 않는다. 중단 시 동일 외부 키로 재연결한다.
- **책임·의존 계약:** Vm이 전원/guest 관찰과 명령 전제, Jobs가 작업 상태, Integrations가 VMM 변환을 소유한다. 강제·원복·디스크 영향은 정책 결정 전 구현 범위 밖이다.
- **코드동작확인 Test방식:** 권한 거부, 진행 중 충돌, graceful/허용 입력, 외부 응답 유실, 늦은/충돌 결과, 재기동을 계약 fixture 및 승인 실환경에서 확인한다. 전원·guest·job 각각의 증거를 대조한다.
- **코드동작확인 로깅방식:** 요청된 동작의 분류·actor·대상·근거·시도 및 실제 관찰을 기록한다. 비밀/명령 원문을 제외하고 감사와 VMM 결과를 맞춘다.
- **완료·반환 증거:** 승인된 stop 의미와 제외 경계, 실패/유실/복구 결과, 강제 종료 및 운영 복구 정책의 미정 사항.

### FS-032 VM 재시작
<a id="fs-032"></a>
- **목적:** 재시작 의도를 하나의 추적 작업으로 처리하고 중간 전원 전이를 실제 관찰과 연결한다.
- **추가 범위:** 재시작 operation과 단계별 외부 증거, 충돌 방지 및 감사.
- **수정 범위:** Jobs 전이 모델은 단일 재시작 요청과 내부/외부 상태 관찰을 구분한다.
- **삭제 범위:** 성공 receipt를 부팅·서비스 준비 증거로 취급하는 동작.
- **goal:** 중간 정지·시작 상태를 유실하지 않고 terminal 작업결과와 VM 전원·guest 결과를 분리한다.
- **non-goal:** graceful/reboot/reset/force 옵션의 우선순위나 자동 재시도 추정.
- **목표-input:** VM 소유권·현재 상태는 Vm, 재시작 의도는 사용자/API, 허용 command와 상태 전이 의미는 G1 VMM 계약이 공급한다.
- **목표-output:** 재시작 job, 단계별 관찰 참조, 최종 확인/미확정 결과.
- **구현 동작:** 권한·mode·상태·중복 operation 검증 → 멱등 요청 식별 → job/outbox/audit 원자 저장 → 외부 호출 시 DB 잠금 해제 → 응답/통지/상태를 attempt 및 대상과 대조 → 근거 있는 상태만 기록. 중도 중단은 reconciliation으로 두며 단순 응답 누락에 새 재시작을 발행하지 않는다.
- **책임·의존 계약:** Jobs가 작업·단계 증거, Vm이 전원 및 guest 관찰, Integrations가 승인된 재시작 command mapping을 담당한다.
- **코드동작확인 Test방식:** 유효/불가 상태, 이중 요청, 중간 단계 지연·응답 유실·늦은 완료, guest 미준비를 확인한다. attempt 단일효과와 상태 필드 구별을 검사한다.
- **코드동작확인 로깅방식:** 재시작 사건의 요청·단계 관찰·완료/unknown, job/attempt/VM 참조를 기록한다. 접속 정보·명령 원문 없이 외부 사건과 내부 전이를 대조한다.
- **완료·반환 증거:** 승인된 재시작 계약, 단계 관찰과 불명확 복구 결과, guest readiness 분리 근거 및 정책 보류.

### FS-033 VM 삭제·잔여 디스크 처리
<a id="fs-033"></a>
- **목적:** 권한 검증과 명시적 정책 아래 논리 VM 삭제 요청을 추적하고 잔여 자원 결과를 보존한다.
- **추가 범위:** 삭제 작업·위험 확인·외부 결과·잔여 디스크 상태 및 감사 참조.
- **수정 범위:** VM 조회 상태와 삭제 진행/완료 상태를 구분하고 보존된 잔여 자원을 노출 가능한 형태로 기록한다.
- **삭제 범위:** 사용자/정책 근거 없는 디스크 삭제, 자동 정리, 강제 종료, 되돌릴 수 없는 제거를 확정하지 않는다.
- **goal:** G1에서 확정된 삭제 대상·보존/정리 정책에 한해 단계와 잔여 자원 결과를 증거화한다.
- **non-goal:** 물리 디스크 삭제·원복 가능성·보존 기간을 임의 결정하거나 구현하는 것.
- **목표-input:** actor·권한은 Identity, VM과 연결 자원은 Vm/VMM 관찰, 삭제/잔여 디스크 규칙은 G1 결정이 공급한다.
- **목표-output:** 접수 작업, 삭제 결과, 남은 디스크/자원 관찰 및 미확정 항목을 운영자와 사용자에게 제공한다.
- **구현 동작:** 강한 권한 및 대상/소유권 확인 → 진행 중 작업·영향·승인 정책 검사 → 허용된 선택에 대해서만 단일 트랜잭션 job/outbox/audit → 외부 실행 분리 → 응답·늦은 통지·조회 근거 검증 및 잔여 자원 기록. 응답 유실은 unknown이고 재기동 후 외부 키로 연결한다. 정책이 미정이면 destructive 실행을 차단한다.
- **책임·의존 계약:** Vm은 자원 관계/삭제 상태, Jobs는 실행 추적, Integrations는 승인 명령 변환, Audit는 행위 근거를 소유한다. 실제 디스크 처리와 복구/원복 정책은 G1 결정 게이트다.
- **코드동작확인 Test방식:** 역할 거부, 확인 누락, 종속/잔여 자원 경계, 외부 실패·응답 유실·재시작·늦은 이벤트를 안전한 격리 대상에서 검증한다. 미정 정책에서는 외부 호출 없음과 보존 상태를 확인한다.
- **코드동작확인 로깅방식:** 요청 actor·VM/job·정책 결정 참조·단계·잔여 결과만 기록하고 내부 주소/명령/비밀은 제거한다. 감사·VMM 결과·자원 관찰을 대조한다.
- **완료·반환 증거:** 승인된 삭제/보존 정책, 격리 검증 결과, 잔여 디스크 관찰과 재기동 복구, 미결 G1 결정 목록.

### FS-034 VM 사양 변경·적용 이력
<a id="fs-034"></a>
- **목적:** 허용 사양 변경 의도를 작업으로 추적하고 요청 사양과 외부 적용 사양을 구별한다.
- **추가 범위:** 사양 변경 job, 이전/요청/관찰된 적용 사양 참조와 감사 이력.
- **수정 범위:** VM의 현재 사양 표시는 VMM 결과/상태 관찰로 확인된 적용 사양을 기준으로 한다.
- **삭제 범위:** 접수 즉시 현재 적용 사양 변경, 청구/자원 영향을 미확정 규칙으로 계산하는 동작.
- **goal:** 사양 허용성·VM 상태·동시 변경을 검증하고 실제 적용 결과만 이력화한다.
- **non-goal:** G1에서 확인하지 않은 CPU/RAM/디스크 한도, 온라인 변경 가능성, 자동 원복 또는 청구 정책 확정.
- **목표-input:** 허용 profile은 FS-010, VM/기존 적용 사양은 Vm, 자원 capability·실제 규칙은 G1 VMM 계약이 공급한다.
- **목표-output:** 요청/접수 작업과 확인된 applied profile 및 변경 이력을 조회자에게 제공한다.
- **구현 동작:** 권한·VM 상태·profile 활성 및 capability 검증 → 기존 변경 작업과 경합 검사 → 멱등 적용 → job/outbox/audit 원자 저장 → 외부 호출 중 잠금 해제 → receipt만으로 applied 처리하지 않고 callback/StatusReader 증거 검증 → 이전/적용 사양 이력과 VM current 참조를 원자 갱신. 실패/불명확은 요청 사양과 현재 적용값을 분리한다.
- **책임·의존 계약:** Vm은 사양 관계와 적용 이력, Jobs는 변경 실행, Integrations는 허용된 mapping, Billing은 후속 단계에서 실제 구간을 소비한다. P 단계에는 Billing 효과가 없다.
- **코드동작확인 Test방식:** 유효/비활성 profile, capability 거부, 진행 중 변경, receipt-only, 지연·실패·재기동 후 완료를 검사한다. applied profile 변경은 근거가 있을 때만 발생하고 이력·VM current의 원자성을 확인한다.
- **코드동작확인 로깅방식:** 이전/요청/적용 profile 참조, actor, job/attempt, 관찰 근거 및 전이 결과를 기록한다. 실제 세부 환경·자원 주소는 제외하고 이력 DB와 VMM 관찰을 대조한다.
- **완료·반환 증거:** 변경 capability 계약, 적용 전후 사양 근거, 실패/미확정의 보존 결과, 용량·온라인 변경·원복 관련 G1 보류.
