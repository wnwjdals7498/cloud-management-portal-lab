# 단계와 확인 항목

원문: [1차 구현 계획](../implementation-plan-v1.md) 1·3·12절. [참조 안내](README.md).

## 자원 확인

| 게이트 | 확인 항목 | 통과 시 진행 |
| --- | --- | --- |
| G0 | PHP·확장·Composer·MySQL·로컬 웹 경로, 버전·접속·테스트 DB·개발 자원 측정 | Prototype P0~P4 |
| G1 | 실습 CPU·중첩 가상화·디스크·자원·라이선스·네트워크, IIS 수신부 기술·MSSQL 조회 대상 | 실제 연동 E 단계 |
| G2 | 운영 한도·백업 매체·복구 시간·계정·인증서·4+4 기동과 감시 | Production 완료 판정 |

2026-10-01 계획 작성 시 PHP·Composer는 개발 PC PATH에서 미발견, MySQL은 미확인, Docker 엔진은 연결 실패였다. 재개 시 다시 확인한다. 별도 64GB 실습 PC의 CPU·디스크·제품 사용 권한은 사용자 미확인이다. 개발 PC의 측정값을 실습 PC에 적용하지 않는다.

## 작업 순서

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| P0 | 환경·버전 잠금·API/상태/모의 설정 계약 | 환경 목록·계약·잘못된 설정의 기동 거부 |
| P1 | 고객·관리자·API·모의 앱 골격·인증·초기 Audit append 기반 | 관리자 1·회원 2, 로그인·권한·CSRF 차단 및 계정 감사 검증 |
| P2 | 고정 사양 신청·VM·작업·outbox·감사 저장 | 멱등 키 재제출 동일 작업, 다른 본문 409 |
| P3 | 무작위 모의 연동·dispatcher·inbox·조회 | 5개 시나리오 및 재시작 후 예정 통지 복구 |
| P4 | 화면·로그·통합 검증 | 실제 VM 없이 신청부터 결과까지 일치 |
| E0~E1 | 인프라·Linux 별도 검증, 실제 VMM·MSSQL 연동 | 4+4 환경에서 고객 VM 생성·부팅·SSH |
| E2~E4 | VM 전체 동작·청구·인프라 제어·알림 | 실제 결과·권한·장애·계산 검증, SMS/테스트 PG 조건부 결정 |
| R1~R3 | 배포·보안·감시·백업·복구·운영 한도 | 재부팅·복원·롤백·인증서 갱신과 G2 통과 |

인프라 8대와 Linux 8대는 따로 시험한 뒤 각각 4대로 축소한다. 상시 4+4는 역할별 단일 노드이며 물리 호스트도 1대다. Galera와 서비스 MySQL은 분리한다. 각 단계의 구체 작업과 증거는 원문 표를 따른다.

G0·P0~P4의 로컬 Prototype 검증은 [구현·검증 기록](../operations/prototype-progress.md)에 연결한다. 다음 실제 연동은 G1 확인 후 진행한다. 별도 실습 자원을 개발 PC 측정값으로 대체하지 않는다.
