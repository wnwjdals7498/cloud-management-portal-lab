# Linux IaaS·고가용성 세부 계획

기존 `linux-iaas-ha-lab`의 계획을 통합한 문서다. 현재는 계획 단계이며 VM·클러스터·VPC 구현과 검증 전이다. PHP·CodeIgniter 포털은 인프라의 상태를 보여주고 허용된 제어 작업을 요청한다. Rocky Linux, MariaDB, Nginx, Keepalived 및 네트워크 구성 자체는 각 기술의 실행 환경에서 구축한다.

## 목표

Rocky Linux 10 계열 VM에서 MariaDB Galera, 접근 경로, VPC와 제어 기능을 작은 환경부터 구현·검증한다. 모든 장애 결과에는 단일 물리 호스트라는 시험 범위를 명시한다.

## 단계

1. 호스트 CPU의 Rocky Linux 10 호환성, VM 자원과 네트워크 조건을 확인한다. 지원 마이너 버전을 선택한다.
2. Rocky Linux VM 한 대를 수동 설치하고 SSH·방화벽·패키지·네트워크를 설정한다.
3. Hyper-V 템플릿과 VM 복제를 재현하고 단일 MariaDB를 구성한다.
4. MariaDB Galera 데이터 노드 2개를 구성한다. 정족수 후보는 공식 문서와 시험으로 비교해 사용자에게 제시하고 **최종 구성은 사용자가 지정한다**. 후보는 별도 소형 VM의 `garbd`, 데이터 노드와 같은 VM의 Arbitrator, `pc.weight`다. 특정 노드를 우대하는 가중 투표를 두 노드 모두에 대한 대칭적 장애 내성으로 간주하지 않는다.
5. 삽입·삭제 동기화, 동시 수정·삭제의 충돌·잠금·트랜잭션 결과를 검증한다. 데이터 노드 한 대 중지 시 서비스 지속, 재시작 후 재합류·일관성과 네트워크 분리 결과를 기록한다.
6. Nginx·Keepalived 접근 경로를 구성하고 장애 시 동작을 검증한다.
7. VPC를 구현하고 네트워크 분리·연결 동작을 검증한다. 구현 기술은 사용자가 지정한다. nftables·namespace 기반 Gateway는 기존 검토 후보이며 확정 기술이 아니다.
8. 포털에서 VPC와 필요한 Linux 인프라의 상태를 조회하고 제어 작업을 요청한다. 제어 기술도 사용자가 지정한다. Go Executor/API는 기존 검토 후보이며 확정 기술이 아니다. 화면의 완료·실패 표시는 실제 실행 결과와 맞춘다.

## 완료 확인

- Galera의 한 데이터 노드 장애·재합류 실험과 데이터 일관성 결과가 재현 가능하다.
- Nginx·Keepalived 경로와 VPC의 실제 네트워크 동작을 검증한다.
- 포털의 인프라 상태와 제어 작업 이력이 실제 환경과 일치한다.
- 테스트한 장애 범위, VM 사양, 정족수 조건과 단일 물리 호스트의 한계를 기록한다.

## 이후 결정

Galera 투표 구성, 세부 제품 버전, 동시 작업 테스트 데이터·판정 기준, VPC의 세부 기능과 구현·제어 기술을 해당 단계 전에 정한다. Podman·Kubernetes는 이 프로젝트의 완료 조건에 포함하지 않는다.
